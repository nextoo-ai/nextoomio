## What the check does

Three rules, and nothing else (the script's docstring states the same):

1. In the header of SPECIFICATION.md, ROADMAP.md, and ARCHITECTURE.md (the lines before the first `## ` heading), a version stated for another of the three documents (a Markdown link to the document followed by `version N`) must equal that document's own `Document version`.
2. In README.md, a version stated for one of the three documents (`` `vN` `` or `version N` after a mention of the document) must equal that document's own `Document version`. A release range such as `` `v0.0.1–v0.0.5` `` is not read as a document version.
3. Every explicit reference of the form `<document> section <n>` (also `sections 10–11`, `§`), where the document is SPECIFICATION, ROADMAP, or ARCHITECTURE, with or without `.md`, with or without backticks around the name, or as the lower-case word, in the maintained Markdown files (the set of `scripts/check_traceability.py`, `SK/` excluded) must point to a numbered heading of that document.

Version numbers in version notes, decision records, and other body text are not compared. Prose is not checked. References that do not name one of the three documents next to the word "section" (for example a reference to a section of the same document, or a document name followed by other words before "section") are not recognized and not checked.

## Not checked

- A CI run of the check on the final pull request for this story (the pull request for `2f7ec31` and this file) is shown by that pull request's own checks, not by this file.
- The check was not run on any Windows or other non-POSIX environment; CI uses `ubuntu-24.04` with Python 3.12, and the local runs used `python3` on macOS.
- Phrasings of a cross-reference outside the pattern in rule 3 are not detected (for example a reference written as "see the architecture, section 5", with a comma after the word and no link, is recognized, but "in section 5 of the architecture" is not).
- Besides the closing backtick, no other decoration of the document name is accepted: a name inside bold or italic markers, or a link whose text is not the document name followed directly by "section", is not detected.
- #69 (D-037) is listed under "Defects resolved by this story". `AGENTS.md` already names `ARCHITECTURE.md` as a source of truth and is an Architect-owned file; this work did not change it and does not show that the defect is resolved.

## Review round 1

The review of `aa850c9` found that the pattern of rule 3 did not accept a closing backtick after the document name, so three existing references were never checked. `bb43d5e` accepts an optional backtick; nothing else in the script changed. The CI demonstration of a version mismatch (#156, `dd85e27`, above) ran the script from `2f7ec31`. It stays valid for rule 1, because `bb43d5e` changes only the section-reference pattern; it does not show rule 3. CI for `bb43d5e` is shown by this pull request's own checks.
