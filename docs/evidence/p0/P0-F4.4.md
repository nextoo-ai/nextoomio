## Procedure

1. **Partition abstraction and sound-card hardware include management (AC1, AC4, SYS-05, UPD-05):**
   - Extended `Slot` and `PartitionType` (`Boot`, `Root`) in `core/crates/nx-sysd/src/system.rs` mapping system slot partitions to physical block devices per ARCHITECTURE.md section 3.6:
     - Slot A: boot `/dev/mmcblk0p2` (`boot_a`), root `/dev/mmcblk0p5` (`root_a`)
     - Slot B: boot `/dev/mmcblk0p3` (`boot_b`), root `/dev/mmcblk0p6` (`root_b`)
   - Extended `SlotBackend` trait with typed operations:
     - `checksum_partition(slot, partition)`: computes SHA-256 of entire partition contents.
     - `write_partition(slot, partition, reader, size)`: streams artifact bytes into target partition with in-place overwriting (`truncate(false)`) and syncs writes.
     - `read_partition_checksum(slot, partition, length)`: reads back written partition data up to artifact length and computes SHA-256.
     - `get_active_sound_card_selection()`, `get_sound_card_selection(slot)`, and `set_sound_card_selection(slot, content)`: manages `nextoomio-hardware.txt` sound-card overlay include.
     - `sync_partitions()`: executes POSIX `sync(2)` and file flushes.
   - Implemented `MockSlotBackend` for deterministic unit testing with partition write logging (`written_partitions`), active partition leak injection (`write_active_slot_glitch`), and readback corruption simulation (`corrupt_readback`).
   - Implemented `PhysicalSlotBackend` targeting real block devices and Linux mount points:
     - For inactive slot hardware configuration retention (`set_sound_card_selection` / `get_sound_card_selection`), mounts the target boot partition (`/dev/mmcblk0p2` or `/dev/mmcblk0p3`, vfat) via `ScopedBootMount`, writes/reads `nextoomio-hardware.txt`, flushes, and unmounts upon completion.
     - Supports environment variable overrides (`NEXTOOMIO_SLOT_A_BOOT`, `NEXTOOMIO_SLOT_A_ROOT`, `NEXTOOMIO_SLOT_B_BOOT`, `NEXTOOMIO_SLOT_B_ROOT`, `NEXTOOMIO_ACTIVE_BOOT_DIR`, `NEXTOOMIO_INACTIVE_BOOT_DIR`) for end-to-end multi-process verification without requiring physical disk hardware or root mount privileges.

2. **Inactive slot installation, active slot preservation, and readback verification (AC1, AC2, AC3, AC4, SYS-05, UPD-05):**
   - Implemented `UpdateEngine::install(&mut self)` in `core/crates/nx-sysd/src/engine.rs`:
     - Enforced precondition that current transaction state must be `Validated` (`begin_install`), refusing installation from `Idle`, `Receiving`, `Staged`, `Failed`, or `Installed` with `InvalidStateTransition` or `Busy` (AC3).
     - Persists durable transaction state `Installing` in the alternating journal (`journal.0` / `journal.1`) and syncs to disk before writing any partition (AR-01, ARCHITECTURE.md section 3.6 step 3).
     - Computes SHA-256 checksums of active boot and active root partitions before writing (AC1).
     - Resolves declared boot and root artifacts for `target_slot = active_slot.inactive()` from `sw-description` inside the staged container, requiring exact device path match (`target_slot.boot_device()` and `target_slot.root_device()`), refusing mismatched devices with `InvalidFormat`.
     - Streams artifact entries incrementally from the staged CPIO archive using `Read::take`, writing ONLY the inactive boot and root partitions, propagates padding read errors, and flushes writes via `sync_partitions()` (AC1).
     - Recomputes SHA-256 checksums of active boot and active root partitions, verifying that active slot partitions are completely identical before and after installation (AC1).
     - Reads back written data from inactive boot and inactive root partitions up to artifact length, computes SHA-256, and verifies exact match with declared artifact digests. Mismatches abort installation and transition to `Failed` (`update_corrupted_artifact`) without becoming `Installed` (AC2).
     - Copies running slot's sound-card selection (`nextoomio-hardware.txt`) into the newly written inactive boot slot partition (mounting vfat if not overridden), flushes, and reads back to verify that the identical hardware configuration is present on disk (AC4).
     - On successful verification of all criteria, persists durable transaction state `Installed` bound to transaction ID and target slot (AC2).
     - Resets staging payload metadata in place via `cleanup()` without releasing or shrinking preallocated extents.

3. **Interrupted installation recovery and boot reconciliation (AC5, AR-01, UPD-05):**
   - Extended `JournalController::reconcile_boot(&mut self)` in `core/crates/nx-sysd/src/journal.rs` to reconcile unfinalized `Installing` records to `Failed` (`update_truncated`).
   - When power loss or reboot occurs during an install:
     - The alternating journal retains `Installing` with generation counter and CRC32 checksum.
     - On reboot, `nextoomio-update-init.service` invokes `/usr/bin/nx-sysd update init-staging` before `basic.target`.
     - `reconcile_boot()` reconciles `Installing` state to `Failed` (`update_truncated`), leaving `active_slot` and `default_slot` set to the previous good slot.
     - The state is not `Installed`, and trial boot of the incomplete slot cannot be requested (AC5).

4. **CLI subcommand and REST API specification:**
   - Implemented `nx-sysd update install [--dir <path>] [--hardware <id>] [--schema <n>] [--capacity <bytes>]` in `core/crates/nx-sysd/src/main.rs`.
   - Updated REST API description in `docs/api/openapi.yaml` documenting `POST /update/install` returning `UpdateStatus` on success (200) or `ApiErrorResponse` on failure (400).

5. **Recorded CLI end-to-end execution across separate processes:**

## Missed targets

In accordance with the project owner's decision of 2026-11-15 and the Architect's instructions for issue #20, all Phase 0 software is implemented and statically verified first in author sessions, while full image builds and hardware measurements run on `main` and the bench device afterwards. The following items require an image build and physical bench hardware:
- **Build verification:** BitBake image build (`kas build kas/rpi4-64.yml`) to produce full image containing updated `nx-sysd` binary will be verified on `main`.
- **AC1:** Runtime verification on physical Raspberry Pi 4 that `/dev/mmcblk0p2` (`boot_a`) and `/dev/mmcblk0p5` (`root_a`) partition checksums before and after install over SSH are identical, and only `/dev/mmcblk0p3` (`boot_b`) and `/dev/mmcblk0p6` (`root_b`) are written.
- **AC2:** Runtime readback of physical MMC partitions `/dev/mmcblk0p3` and `/dev/mmcblk0p6` on bench device matching `.swu` artifact digests.
- **AC4:** Physical VFAT mount and sound-card audio test on bench hardware (HiFiBerry Amp+): verifying that `PhysicalSlotBackend` mounts `/dev/mmcblk0p3` (read-write, vfat), writes `nextoomio-hardware.txt`, unmounts, reads back from the mounted partition, and boots into the trial slot with ALSA driver loaded.
- **AC5:** Trial boot prevention and recovery on physical hardware: bench power cut during `nx-sysd update install` verifying the bootloader reboots into the previous slot (Slot A), journal reconciliation marks the transaction `failed` (`update_truncated`), state is not `installed`, and trial boot of the incomplete slot cannot be requested (P0-F4.5 dependency).
