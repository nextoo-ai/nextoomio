## Procedure

1. **Artifact download command and pattern matching (Actual item 1):**
   - Corrected `docs/bench/first-flash.md` section 3.1 step 2: replaced exact match flag `-n "nextoomio-rpi4-64-*"` with glob pattern matching `-p "nextoomio-rpi4-64-*"` as documented in `gh run download --help`.

2. **Extraction directory handling (Actual item 2):**
   - Added `--dir nextoomio-rpi4-64` to `gh run download <RUN_ID> -p "nextoomio-rpi4-64-*" --dir nextoomio-rpi4-64` in `docs/bench/first-flash.md` section 3.1 step 2 to ensure that the single matched artifact is extracted into that dedicated directory rather than the current working directory, as documented in `gh run download --help`.

3. **Artifact directory structure and colocation (Actual item 3):**
   - Updated `docs/bench/first-flash.md` section 3.1 step 3 to document the directory hierarchy created by `actions/upload-artifact@v4` under `build/**/deploy/`:
     - Flashable image and block map: `build/tmp/deploy/images/raspberrypi4-64/*.wic.bz2` and `build/tmp/deploy/images/raspberrypi4-64/*.wic.bmap`
     - Manifests and SBOM: `build/tmp/deploy/images/raspberrypi4-64/*.manifest` and `build/tmp/deploy/images/raspberrypi4-64/*.spdx.tar.zst`
     - License manifest: `build/tmp/deploy/licenses/**/license.manifest`
   - Instructed changing into `build/tmp/deploy/images/raspberrypi4-64` before executing `bmaptool copy` so that the `.wic.bmap` block map and `.wic.bz2` image reside in the same directory.
   - Internal directory hierarchy verified as observed by Architect on 2026-11-16 via `gh run download 43832700635` from full-image CI build on `main` at commit `cd9505ebf246747fea8b9f11680a14a6921cf874`: all published files reside under `build/tmp/deploy/`.

4. **Workflow run filtering and artifact verification (Actual item 4):**
   - Added `gh run view <RUN_ID>` instruction to verify that a selected successful run on `main` performed a full-image build and published artifacts, distinguishing full builds from fast recipe parse verification (`parse-only`) runs which publish no artifacts.

5. **Storage card capacity specification (Actual item 5):**
   - Corrected `docs/bench/first-flash.md` section 2 line 29 from "At least **16 GB** (16 GiB)" to "At least **16 GB** (nominal capacity)". This resolves the discrepancy where nominal 16 GB (~14.9 GiB) was conflated with 16 GiB, while aligning with the 8256 MiB layout reasoning.

6. **Distinction of planned vs implemented update deployment (Actual item 6):**
   - Reworded section 1 line 7 and section 9 in `docs/bench/first-flash.md` to state that subsequent network image deployments through the update engine, trial boot, and commit are planned behaviors under stories P0-F4.2–P0-F4.6 rather than currently implemented or hardware-verified behaviors, in compliance with `AGENTS.md`.

7. **Documentation quality checks:**
   - Ran `python3 scripts/check_traceability.py`, `python3 scripts/check_doc_versions.py`, `python3 scripts/check_evidence.py --test`, `python3 scripts/check_evidence.py`, and `make check`.
