## Procedure

1. **AC1 (Run stops while checkout is on a change branch with a clean working tree ends on `main` with the stop exit status):**
   - Implemented `cleanup_checkout(cwd=None)` in `scripts/agent-pipeline.py`:
     - Inspects current branch via `git branch --show-current` (with fallback to `git rev-parse --abbrev-ref HEAD` / `git rev-parse --short HEAD` for detached commits).
     - When checkout is already on `main` or no branch ref exists, returns with no action.
     - When checkout is on a change branch and `git status --porcelain` is clean, switches back to `main` via `git switch main` (logging failure message if switch fails).
   - Updated `main(argv=None, cwd=None, run_dir=None)`:
     - Wrapped pipeline execution in a `try...finally: cleanup_checkout(cwd=cwd)` block.
     - Caught `Stop` exceptions, printed the error message via `say(str(stop))`, and ensured `cleanup_checkout` runs in `finally` before returning the stop exit status (`stop.status`).
     - Caught unhandled exceptions and `KeyboardInterrupt`, logged via `say(...)` (recording traceback to `agents.log` if initialized), and ensured `cleanup_checkout` runs in `finally` before returning status 1.
   - Tested offline in a temporary git repository:
     - Initialized `d047_origin` repository on `main` with an initial commit.
     - Cloned `d047_origin` into `d047_local`.
     - Configured author tooling with a failing agent script (exiting 1 without modifying the working tree).
     - Executed `main(["188", "--role", "devops"], cwd=d047_local)` with mocked `gh` issue view response.
     - Verified post-conditions: returned exit status is 1 (the stop exit status), `d047_local` checkout is on `main`, and working tree is clean.

2. **AC2 (Run stops while checkout is on a change branch with uncommitted changes leaves changes untouched, stays on the change branch, and names the branch in its last message):**
   - In `cleanup_checkout(cwd=None)`:
     - When checkout is on a change branch and `git status --porcelain` is non-empty (uncommitted changes present), does not switch to `main` and leaves the working tree untouched.
     - Emits `say(f"the working tree is not clean; checkout left on {branch}")` as the final message before the program ends.
   - Tested offline in a temporary git repository:
     - Configured author tooling with an agent script that creates an uncommitted file `uncommitted_work.txt` in `d047_local` and exits 1.
     - Executed `main(["188", "--role", "devops"], cwd=d047_local)` with recorded `say()` messages.
     - Verified post-conditions: returned exit status is 1, `d047_local` checkout remains on `ops/D-047-pipeline-test`, `uncommitted_work.txt` is untouched with its original content, and the last recorded message emitted by the pipeline contains `ops/D-047-pipeline-test` and states `the working tree is not clean; checkout left on ops/D-047-pipeline-test`.

3. **AC3 (`python3 scripts/agent-pipeline.py --test` runs without network, exits 0, and covers AC1 and AC2):**
   - Added Test 10 to `run_self_tests()` in `scripts/agent-pipeline.py` covering AC1 and AC2 using temporary git repositories without network and without starting a real role.
   - Executed `python3 scripts/agent-pipeline.py --test` to confirm it exits 0.
   - Executed `python3 scripts/check_evidence.py`, `python3 scripts/check_traceability.py`, `python3 scripts/check_doc_versions.py`, `node scripts/check_i18n.mjs`, and `make check` to verify repository consistency, evidence validation, and quality gates.
