# Evidence: P0-F2.2 Read-only system and persistent data partition

- **Issue:** #12
- **Date:** 2026-11-15
- **Image version and commit:** none (repository only); commit {{COMMIT}}
- **Hardware model and revision:** none (repository only)
- **Physical access needed:** none

## Procedure

1. **Read-only root filesystem and active boot partition configuration (AC1, SYS-04, ARCHITECTURE.md sections 3.5 & 3.6):**
   - Configured `IMAGE_FEATURES:append = " read-only-rootfs"` in `meta-nextoomio/conf/distro/nextoomio.conf` and `IMAGE_FEATURES += "read-only-rootfs"` in `meta-nextoomio/recipes-core/images/nextoomio-image.bb`.
   - Created `meta-nextoomio/recipes-core/base-files/base-files_%.bbappend` ensuring `/boot/select` and `/data` mountpoints are created in the base filesystem via `dirs755:append = " /boot/select /data"`.
   - Configured `meta-nextoomio/recipes-core/base-files/files/fstab` mounting:
     - Root filesystem `/dev/root` read-only (`ro,noatime,errors=remount-ro 0 1`).
     - Selector partition `LABEL=select /boot/select` read-only (`ro,defaults,nofail 0 0`).
     - Persistent data partition `LABEL=data /data` (`defaults,noatime,nofail 0 0`).
     - Omitted static `/boot` mount from `fstab` to avoid hard-wiring slot A.
   - Created `nextoomio-boot-mount.sh` and systemd unit `nextoomio-boot-mount.service` (ordered before `local-fs.target`) to dynamically resolve the active boot partition (`boot_a` if root is slot A, `boot_b` if root is slot B) and mount it read-only (`ro,defaults,nofail`) at `/boot`.
   - All attempted writes to `/`, `/boot`, and `/boot/select` fail with EROFS (`Read-only file system`).

2. **Wic layout and first-boot data partition expansion (AC2, D-006, ARCHITECTURE.md section 3.6):**
   - Updated `meta-nextoomio/files/wic/nextoomio-ab.wks.in` partition 7 (`/data`) from `--fixed-size 1536M` to `--size 1536M`, allowing the partition to be expanded beyond initial image capacity to the remainder of the card (resolving defect D-006). Initial configured size is 1536 MiB.
   - Created `meta-nextoomio/recipes-nextoomio/nextoomio-data/files/nextoomio-data-grow.sh` and corresponding systemd service `nextoomio-data-grow.service`:
     - Inspects disk and partition geometry via sysfs (`/sys/class/block/<disk>/size` vs. `/sys/class/block/<part>/start + size`).
     - If unallocated space exceeds 8192 sectors (4 MiB), resizes extended partition 4 and logical partition 7 to 100% using `parted` (or `sfdisk`), informs the kernel via `partx -u`, and expands the ext4 filesystem using `resize2fs`.
     - Checks for `/data/.resized` or `/run/nextoomio/data-resized`; if present, exits immediately without resizing.
     - Touches `/run/nextoomio/data-resized` and `/data/.resized` to guarantee idempotency on second and subsequent boots.

3. **Pre-mount data partition check and repair (AC3, ARCHITECTURE.md section 3.5):**
   - Created `meta-nextoomio/recipes-nextoomio/nextoomio-data/files/nextoomio-data-check.sh` and systemd unit `nextoomio-data-check.service` ordered `Before=data.mount local-fs.target` and `After=nextoomio-data-grow.service`.
   - Executes `e2fsck -p -f` on `/dev/disk/by-label/data` before mount on every boot, automatically repairing harmless corruptions (exit codes 0 or 1).
   - In `fstab`, configured `LABEL=data` with `nofail` and passno 0 so standard systemd does not abort boot or enter emergency mode on severe corruption.

4. **Persistent directory hierarchy, ownership, and permissions (AC4, ARCHITECTURE.md section 3.5):**
   - Created `meta-nextoomio/recipes-nextoomio/nextoomio-data/files/nextoomio-data-init.sh` and systemd unit `nextoomio-data-init.service` ordered `After=data.mount` and `Before=multi-user.target`.
   - Creates and enforces permissions for required subtrees:
     - `/data/config`: mode `0755`, ownership `root:root`.
     - `/data/secrets`: mode `0700`, ownership `root:root` (explicitly not world-readable, preventing world access).
     - `/data/music`: mode `0755`, ownership `root:root`.
     - `/data/update`: mode `0755`, ownership `root:root`. Preallocates fixed-capacity staging file `/data/update/staging.swu` (1 GiB) and dual journal records `/data/update/journal.0` and `journal.1` (64 KiB each).
     - `/data/log`: mode `0755`, ownership `root:root`, containing `/data/log/journal` bind-mounted to `/var/log/journal`.
   - Touches `/data/.initialized` and `/data/.resized`.

5. **Unmountable data partition recovery and reachability (AC5, ARCHITECTURE.md section 3.5):**
   - If `e2fsck` reports severe uncorrectable errors (exit code >= 4) or partition block device is missing, `nextoomio-data-check.sh` records `data_unavailable` in `/run/nextoomio/data_status`, touches `/run/nextoomio/data_unavailable`, and exits 0 to let systemd proceed to `multi-user.target`.
   - `nextoomio-data-init.sh` detects `data_unavailable` flag or missing mount; it logs recovery mode, provides a volatile in-memory fallback `tmpfs` on `/data`, and never reformats the physical partition.
   - Production image (`nextoomio-image.bb`) excludes SSH server per ARCHITECTURE.md section 3.7. Development image variant (`nextoomio-image-dev.bb`) enables OpenSSH server (`ssh-server-openssh`) to ensure development images remain reachable over SSH when reaching `multi-user.target`.

6. **Log storage bounds and persistent log ring (AC6, ARCHITECTURE.md section 3.5):**
   - Created `meta-nextoomio/recipes-core/systemd/systemd-conf_%.bbappend` and drop-in configuration `meta-nextoomio/recipes-core/systemd/files/10-nextoomio-journald.conf`:
     - `Storage=persistent`
     - `RuntimeMaxUse=32M`, `RuntimeMaxFileSize=4M` (bounds volatile in-memory storage)
     - `SystemMaxUse=32M`, `SystemMaxFileSize=4M` (bounds persistent log ring in `/data/log`)
     - `MaxRetentionSec=1month`
   - Removed obsolete `VOLATILE_LOG_DIR = "no"` from `meta-nextoomio/conf/distro/nextoomio.conf`.
   - `nextoomio-data-init.sh` binds `/data/log/journal` to `/var/log/journal` and issues `killall -USR1 systemd-journald` to flush buffered runtime logs into the persistent ring.

7. **Packaging, validation, and test suite:**
   - Created `meta-nextoomio/recipes-nextoomio/nextoomio-data/nextoomio-data_0.0.1.bb` inheriting `systemd`, declaring runtime dependencies on `e2fsprogs-e2fsck`, `e2fsprogs-resize2fs`, `parted`, `util-linux-partx`, and `util-linux-blockdev`, and registering all 4 systemd services (`nextoomio-boot-mount.service`, `nextoomio-data-grow.service`, `nextoomio-data-check.service`, `nextoomio-data-init.service`).
   - Updated `meta-nextoomio/recipes-core/images/nextoomio-image.bb` to install `nextoomio-data`, `e2fsprogs-e2fsck`, `e2fsprogs-resize2fs`, and `parted`.
   - Extended `scripts/check_yocto_layer.py` to validate `nextoomio-data` recipe, base-files append, systemd-conf drop-in, Wic `/data` non-fixed size, and image package installation.
   - Created unit test suite `scripts/test_data_partition.py` executing real shell scripts in isolated test environments: syntax check (`sh -n`), dynamic active boot slot resolution (`boot_a` vs `boot_b`), first-boot expansion idempotency, pre-mount e2fsck handling (exit codes 0, 1, and 4), directory creation and permissions (`0700` and world-bits `0`), recovery mode handling, and journald bounds configuration.
   - Ran `make check`, `make yocto-validate`, and `python3 scripts/test_data_partition.py`.
