## Procedure

1. **Implementation of the three deliberately broken test image recipes (AC1, AC2, AC3, AC6):**
   - Implemented `meta-nextoomio/recipes-core/images/nextoomio-image-broken-hang.bb` for **AC1** (early kernel/init hang before systemd):
     - Requires `nextoomio-image.bb` baseline.
     - Replaces `/sbin/init` in rootfs postprocess command with a symlink to `/sbin/nextoomio-hang-early` provided by `nextoomio-test-faults-hang`.
     - When PID 1 is executed by the kernel upon mounting rootfs, it outputs an identification banner to `/dev/console` and loops indefinitely without starting systemd. Note that automatic board reset requires continuous pre-systemd watchdog arming (`kernel_watchdog_timeout` / bootloader watchdog per [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.6 AR-01 and spike S1 / #17).
   - Implemented `meta-nextoomio/recipes-core/images/nextoomio-image-broken-health.bb` for **AC2** (boots systemd but fails local health check prerequisites):
     - Requires `nextoomio-image.bb` baseline.
     - Masks `pipewire.service` and `nextoomio-audio-profile.service` to `/dev/null` in rootfs postprocess command.
     - This directly breaks the local health check prerequisites specified in [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.6 step 5 (PipeWire readiness and configured ALSA audio output initialization).
   - Implemented `meta-nextoomio/recipes-core/images/nextoomio-image-broken-network.bb` for **AC3** (locally healthy but unreachable network / no SSH):
     - Requires `nextoomio-image.bb` baseline.
     - Masks `NetworkManager.service`, `sshd.service`, and `nextoomio-ssh-keys.service` to `/dev/null` in rootfs postprocess command.
     - The local system boots completely healthy (data mounted, audio initialized, local daemons running), but external network connectivity and SSH access are disabled. Under remote confirmation mode ([ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.6 step 6, AD-22), workstation confirmation cannot arrive, and the 120-second trial budget times out.

2. **Implementation of documented build options in kas (AC6):**
   - Created `kas/test-broken-hang.yml` targeting `nextoomio-image-broken-hang`.
   - Created `kas/test-broken-health.yml` targeting `nextoomio-image-broken-health`.
   - Created `kas/test-broken-network.yml` targeting `nextoomio-image-broken-network`.
   - Verified the isolation invariant: normal release builds via `kas/base.yml`, `kas/rpi4-64.yml`, or `kas/ci-hosted.yml` target `nextoomio-image` and contain no references to test fault injection packages.

3. **Static validation tooling and procedure documentation:**
   - Authored `scripts/bench/test_broken_images.py` implementing automated static validation across recipes, kas build options, isolation invariants, and negative tests.
   - Authored comprehensive documentation in `docs/bench/broken-images.md` detailing the test procedures, failure mechanics, watchdog dependencies, and verification commands.

4. **Integration into static verification suite:**
   - Enhanced `scripts/check_yocto_layer.py` to statically validate the presence of all three broken image recipes and kas configurations, enforce isolation from `nextoomio-image.bb`, and execute 21 automated self-tests including deliberate failure detection.
   - Added `check-bench` target to `Makefile` so that `make check` executes `test_broken_images.py --test` automatically.

## Missed targets

In accordance with the project owner's decision of 2026-11-15 and the Architect's instructions for issue #23, all Phase 0 software is implemented and statically verified first in author sessions, while full BitBake image builds and hardware measurements on real bench hardware run on `main` and the bench device afterwards. The following items require an image build and physical bench hardware:
- **AC1:** Runtime deployment, pre-systemd watchdog arming (`kernel_watchdog_timeout` per AR-01 and spike S1 / #17), and physical watchdog reset timing measurements of the kernel hang image on physical Raspberry Pi 4 bench hardware.
- **AC2:** Runtime deployment and 120-second trial budget elapsed time measurement of the failing local health check image on physical bench hardware.
- **AC3:** Runtime deployment and remote confirmation timeout observation of the network-unreachable image on physical bench hardware.
- **AC4:** Physical block device and filesystem verification of data partition preservation across physical power-cycle rollbacks.
- **AC5:** Full end-to-end deployment and durable commit of a valid image immediately following rollback on physical bench hardware.
