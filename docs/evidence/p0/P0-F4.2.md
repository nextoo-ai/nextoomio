## Procedure

1. **SWUpdate update file type and packaging class (AC1, AC2, AC3, D-008):**
   - Maintained `meta-nextoomio/classes/image_types_nextoomio.bbclass` inheriting `image_types` providing image type `swu` with dependency `IMAGE_TYPEDEP:swu = "ext4.gz"` as the single producer of the update file.
   - In `IMAGE_CMD:swu`, implemented creation of boot-slot filesystem artifact `nextoomio-boot.vfat` populated with firmware, kernel (`Image`), device tree blob (`bcm2711-rpi-4-b.dtb`), device tree overlays (`overlays/*`), firmware configuration (`config.txt`), kernel command line (`cmdline.txt`), and derived hardware overlay (`nextoomio-hardware.txt`).
   - Hardened boot-slot assembly: enforced checks with `bbfatal` when required boot files (`Image`, `bcm2711-rpi-4-b.dtb`, `cmdline.txt`, `config.txt`) are absent; removed `|| true` guards from `mcopy` and `mmd` so file copy failures fail the build fatally; configured `mkfs.vfat -F 32 -n "boot" -C "${BOOT_ARTIFACT}" 262144` (262144 1 KiB blocks = 268435456 B) fitting exactly the 256 MiB `boot_a`/`boot_b` slot capacity in [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.6. Compressed boot artifact to `nextoomio-boot.vfat.gz`.
   - Enforced slot and staging size limits per [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.6 step 2:
     - Boot slot: `NEXTOOMIO_BOOT_SLOT_MAXSIZE = "268435456"` (256 MiB).
     - Root slot: `NEXTOOMIO_ROOT_SLOT_MAXSIZE = "3221225472"` (3072 MiB = 3 GiB).
     - Staging reservation: `NEXTOOMIO_STAGING_RESERVATION_MAXSIZE = "1073741824"` (1024 MiB = 1 GiB).
     - Expanded uncompressed sizes are validated against their slot limits; aborts build with `bbfatal` if any artifact or update container exceeds its capacity (AC3).
   - Populated `sw-description` via `sed` substitutions from template file `meta-nextoomio/recipes-support/swupdate/files/sw-description.in`, avoiding heredocs and unindented column-0 lines inside `IMAGE_CMD:swu` that cause BitBake parser failures. Version is taken dynamically from `${DISTRO_VERSION}` (AC1, AC4).
   - Packaged files into `.swu` container via `cpio -ov -H crc` with `sw-description` as the mandatory first file.
   - Enforced unsigned updates without signing keys (`SWUPDATE_SIGNING = ""`, UPD-03, AC2).

2. **SWUpdate runtime package configuration and single producer cleanup (AC1, AC2, CQ-R14):**
   - Maintained `meta-nextoomio/recipes-support/swupdate/swupdate_%.bbappend` setting `SWUPDATE_SIGNING = ""` and installing `/etc/swupdate.cfg` and `/etc/hwrevision`.
   - Maintained `meta-nextoomio/recipes-support/swupdate/files/hwrevision` containing `raspberrypi4-64 1.0` to match the `hardware-compatibility` declaration in `sw-description`.
   - Maintained `meta-nextoomio/recipes-support/swupdate/files/swupdate.cfg` with verbose logging and without cryptographic signature checking.
   - Removed competing recipe `meta-nextoomio/recipes-support/swupdate/nextoomio-update-image.bb` and redundant `SWUPDATE_IMAGES*` variables in `meta-nextoomio/conf/distro/nextoomio.conf`, ensuring `nextoomio-image` is the single producer of `.swu`.
   - Maintained `meta-nextoomio/recipes-support/swupdate/files/sw-description.in` template.

3. **Distro and image configuration updates (AC1, AC4, D-008):**
   - Appended `image_types_nextoomio` to `IMAGE_CLASSES` in `meta-nextoomio/conf/distro/nextoomio.conf`.
   - Configured `IMAGE_FSTYPES = "wic.bz2 wic.bmap ext4.gz swu"` in `meta-nextoomio/recipes-core/images/nextoomio-image.bb`, ensuring both flashable image (`wic.bz2`) and update container (`.swu`) are generated with identical `DISTRO_VERSION` (`0.0.1-dev`).
   - Clarified description in `meta-nextoomio/README.md` to distinguish Phase 0 components (`nx-sysd`) from v0.0.1 planned components (D-008).

4. **Kas and CI workflow updates (AC5):**

   - Updated `.github/workflows/yocto-build.yml` in parse-only verification to check `nextoomio-image` (`bitbake -p nextoomio-image`).
   - Configured `.github/workflows/yocto-build.yml` artifact upload step to publish `build/**/deploy/images/raspberrypi4-64/*.swu` next to `*.wic.bz2` under artifact `nextoomio-rpi4-64-${{ github.sha }}`.

5. **Static validation and automated self-tests:**

   - Added 11 automated self-tests (tests 18–28, 28 total) in `scripts/check_yocto_layer.py --test` verifying that failures are triggered when `swu` is missing from `IMAGE_FSTYPES`, when `hardware-compatibility`, `config-schema-range`, or `sha256` are missing, when size limits are altered, when signing is enabled, when `*.swu` artifact upload is omitted, when `IMAGE_CMD:swu` body has unindented column-0 lines, when boot assembly uses `|| true`, or when competing update image recipes are present.
