## Missed targets

In accordance with the project owner's decision of 2026-11-15 and the Architect's instructions for issue #13, all Phase 0 software is implemented and statically verified first in author sessions, while full image builds and hardware measurements run on `main` and the bench device afterwards. The following items require an image build and physical bench hardware:
- **Build verification:** Full BitBake image build on `main` validating `os-release.bbappend`, `nextoomio-image-version.bbclass`, and compilation of `nx-sysd` with `nextoomio-device-id.service`.
- **AC1:** Runtime SSH query of `nx-sysd version` and `nx-sysd identity` on physical bench device running slot A and slot B.
- **AC2:** Runtime devicetree model verification on physical Raspberry Pi 4 Model B bench hardware.
- **AC3:** First-boot verification on real card confirming `/data/device-id` generation and persistence across reboot, update, and rollback.
- **AC4:** Dual-slot update deployment verifying differing versions reported between slot A and slot B.
