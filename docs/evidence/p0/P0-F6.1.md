## Procedure

1. **Hardware profile correction and safe mixer level (AC2, D-012):**
   - Corrected `fixed_hardware_mixer_percent` from `100` to `30` in `meta-nextoomio/files/hardware-profiles/hifiberry-amp.json` per [SPECIFICATION.md](../../../SPECIFICATION.md) section 2.1 and [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 5.3.
   - Confirmed profile definition specifies `profile_id: "hifiberry-amp"`, `display_name: "HiFiBerry Amp"`, `dtoverlay: "hifiberry-amp"`, `alsa_card_id: "sndrpihifiberry"`, `alsa_mixer_control: "Master"`, `fixed_hardware_mixer_percent: 30`, `default_logical_volume_percent: 30`, `sample_rate_hz: 48000`, `sample_formats: ["S24_LE", "S32_LE"]`, `powers_pi_from_card: true`.

2. **Removal of hard-coded overlay from kas build configuration (AC1, D-011):**
   - Removed `RPI_EXTRA_CONFIG:append = "\ndtoverlay=hifiberry-amp\n"` from `kas/rpi4-64.yml`.
   - Ensured build host configuration contains no hardcoded overlay, preventing drift between build configuration and hardware profiles per [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.8.

3. **Dynamic boot include generation and deployment (AC1, AC3, D-011):**
   - Created `meta-nextoomio/recipes-bsp/bootfiles/rpi-config_%.bbappend` appending `include nextoomio-hardware.txt` to `RPI_EXTRA_CONFIG`.
   - Created `meta-nextoomio/recipes-nextoomio/nextoomio-audio-profile/nextoomio-audio-profile_0.0.1.bb` inheriting `systemd` and `deploy`.
   - In `do_compile`, `nextoomio-audio-profile` dynamically derives `nextoomio-hardware.txt` (`dtoverlay=hifiberry-amp`) from the active hardware profile JSON (`NEXTOOMIO_AUDIO_PROFILE ?= "hifiberry-amp"`) using `python3` JSON parsing (`json.load`) to parse array parameters accurately, generating exactly `dtoverlay=hifiberry-amp` (CQ-R1, CQ-R2).
   - In `do_deploy`, `nextoomio-hardware.txt` is deployed to `${DEPLOYDIR}`.
   - Updated `meta-nextoomio/conf/distro/nextoomio.conf` setting `IMAGE_BOOT_FILES_label-boot_a = "${IMAGE_BOOT_FILES} nextoomio-hardware.txt"` to stage the hardware include into slot A boot partition, while keeping `IMAGE_BOOT_FILES_label-select = "autoboot.txt"` isolated.
   - Updated `meta-nextoomio/recipes-core/images/nextoomio-image.bb` adding `do_image_wic[depends] += "nextoomio-audio-profile:do_deploy"`.

4. **Hardware profile installation and boot-time mixer initialization (AC1, AC2, D-011, D-012):**
   - In `nextoomio-audio-profile_0.0.1.bb`, installed hardware profiles to `/usr/share/nextoomio/hardware-profiles/` and active profile to `/etc/nextoomio/hardware-profile.json`.
   - Created `meta-nextoomio/recipes-nextoomio/nextoomio-audio-profile/files/nextoomio-audio-profile.service` ordered `After=sound.target alsa-restore.service` and `Before=pipewire.service mpd.service`.
   - Created `meta-nextoomio/recipes-nextoomio/nextoomio-audio-profile/files/nextoomio-audio-profile-setup.sh` which checks `/etc/nextoomio/hardware-profile.json`, waits for the configured ALSA card (`sndrpihifiberry`) in `/proc/asound/cards` (preventing confusion with onboard/HDMI audio), applies fixed mixer level (30%) to `Master` control via `amixer -c <card>`, and writes escaped structured diagnostics to `/run/nextoomio/diagnostics/audio.json` and human-readable text to `/run/nextoomio/diagnostics/audio.txt`. Dropped `alsactl store` call to prevent state divergence on the read-only rootfs (AC2, CQ-R1 advisory).
   - Added `nextoomio-audio-profile` to `IMAGE_INSTALL` in `meta-nextoomio/recipes-core/images/nextoomio-image.bb`.

5. **Layer validation and automated self-tests:**
   - Extended `scripts/check_yocto_layer.py` with static checks, recipe derivation verification asserting exact `dtoverlay=hifiberry-amp` line output, and 8 automated self-tests (tests 10–17, out of 17 total in check_yocto_layer.py) covering hardcoded kas overlay detection, mixer level 100% rejection, missing rpi-config include, missing boot_a hardware.txt staging, missing audio profile in image install, missing `alsa_card_id`, `amixer -c` flag enforcement, and invalid derivation detection (CQ-R1, CQ-R2, CQ-R4, CQ-M7).
   - Ran `make check` including `check-docs`, `check-doc-versions`, `check-evidence`, `check-i18n`, and `yocto-validate`.
   - Ran `make check-core` and `make test-core`.
