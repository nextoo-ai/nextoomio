## Procedure

1. **AC1 (Given an open pull request for the issue with no Reviewer verdict on its head commit, when the pipeline starts, then the first role it starts is the Reviewer and the author is not started):**
   - Modified `main()` in `scripts/agent-pipeline.py`: when an open pull request exists for the issue (`find_pr(issue, role)`), `latest_review(number, head)` checks the Reviewer's verdict on the head commit.
   - When no Reviewer verdict exists (`verdict is None`), `skip_author` is set to `True`, local checkout is switched to `main`, and the pipeline proceeds directly to the checks and Reviewer evaluation without starting the author role.
   - Verified via self-test AC1 that the Reviewer is the first role started, no author role is started, and following review approval and auto-merge, QM runs.

2. **AC2 (Given an open pull request whose head commit has a request for changes from the Reviewer, when the pipeline starts, then it starts the author with the task that names the pull request):**
   - When the head commit has `verdict == "CHANGES_REQUESTED"`, `task` is initialized with `f"Pull request {number} for issue {issue} needs changes: the review requested changes. Read the review and the CI result with `gh pr view {number} --comments` and `gh pr checks {number}`, and address them. Follow your role definition."` and checkout is set to `branch`.
   - Verified via self-test AC2 that the author role is started first, and the assigned task names the pull request and states that it needs changes.

3. **AC3 (Given an open pull request approved at its head commit, when the pipeline starts, then it starts no author and no Reviewer and continues with the merge):**
   - When the head commit has `verdict == "APPROVED"`, the review loop is skipped entirely; neither author nor Reviewer is started. The pipeline continues directly with `gh pr merge`, waits for merge, validates `Completes-Story: yes`, updates the issue label to `state:implemented`, and proceeds to QM.
   - Verified via self-test AC3 that neither author nor Reviewer is started, and only QM runs after the merge.

4. **AC4 (Given an open issue with state:implemented and a merged pull request that references it, when the pipeline starts, then the first role it starts is QM):**
   - Modified `main()` to accept open issues with `state:implemented` in addition to `state:ready`.
   - Added `find_merged_pr(issue)` to query merged pull requests referencing the issue (`Refs #<issue>`).
   - Added helper `run_qm_and_close(issue, number, log, run_dir, cwd)` to execute QM verification, check the QM verdict, update acceptance criteria checkboxes, and close the issue on `QM-Verdict: PASS`.
   - When an issue has `state:implemented` and a merged pull request is found, QM is started as the first role without starting author or Reviewer.
   - Verified via self-test AC4 that QM is the first role started and completes verification.

5. **AC5 (Given an issue with no pull request and state:ready, when the pipeline starts, then it starts the author, as before):**
   - When no existing pull request is found and the issue has `state:ready`, `task` is set to `f"Work on issue {issue} ({info['title']}) in repository {REPO}. Follow your role definition."` and the author role is started first, as before.
   - Verified via self-test AC5 that the author role is started first with the initial task.

6. **AC6 (Given the change, when python3 scripts/agent-pipeline.py --test runs, then it exits 0 and covers AC1 to AC5 with substituted GitHub state, without network and without starting a real role):**
   - Added Test 14 to `run_self_tests()` in `scripts/agent-pipeline.py` covering AC1 to AC5 with mock git repositories (`d051_origin`, `d051_local`), mock agent runner, and simulated GitHub API responses.
   - Executed `python3 scripts/agent-pipeline.py --test` and confirmed exit status 0 and all output lines.
   - Executed `python3 scripts/check_evidence.py` and `make` to validate repository quality checks.
