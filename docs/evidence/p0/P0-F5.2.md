## Procedure

1. **First-flash procedure documentation for bare-metal bench rebuild (AC1, AC2):**
   - Authored [docs/bench/first-flash.md](../../bench/first-flash.md) detailing the complete, self-contained procedure for provisioning a blank microSD card from a CI image artifact.
   - Defined target reference hardware: Raspberry Pi 4 Model B and HiFiBerry Amp+ (`hifiberry-amp`) with wired Gigabit Ethernet (`eth0`), passive 4–8 $\Omega$ test speaker, and 12V–18V DC power supply powering the stack via the Amp+ barrel jack ([SPECIFICATION.md](../../../SPECIFICATION.md) section 2.1, [ROADMAP.md](../../../ROADMAP.md) section 2.1).
   - Documented flashing steps using both `bmaptool` (block-mapped image copy) and `bunzip2 | dd`.

2. **Card sizing, public-key provisioning, and card verification (AC2, AD-23):**
   - Stated the minimum card size requirement: at least **16 GB** (16 GiB), derived from the fixed dual A/B partition layout in [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.6 (64 MiB `select`, 256 MiB `boot_a`, 256 MiB `boot_b`, 3 GiB `root_a`, 3 GiB `root_b`, 1.5 GiB initial `data` = ~8.2 GiB initial layout).
   - Documented the verification of the written card:
     - MBR partition table (`--ptable msdos`) with disk ID `0x4e58544d` (`PARTUUID=4e58544d-05` for `root_a`).
     - Fixed sizes and labels for all seven partitions (`select`, `boot_a`, `boot_b`, `root_a`, `root_b`, `data`).
     - Mounting partition 1 (`select`) to verify `autoboot.txt` contents (`tryboot_a_b=1`, `boot_partition=2` under `[all]` and `[tryboot]`) and the absence of slot artifacts (kernels, DTBs, overlays).
   - Documented the public-key copying procedure to partition 1:
     - File name: `authorized_keys` (or `authorized_keys.txt`) in the root of partition 1.
     - Accepted key types: `ssh-ed25519`, `ecdsa-sha2-nistp256`, `ecdsa-sha2-nistp384`, `ecdsa-sha2-nistp521`, or `ssh-rsa` with minimum 3072 bits.
     - Format constraints enforced by `nextoomio-ssh-keys`: maximum 16 KiB (16,384 bytes), maximum 16 keys, one key per line, no key options, Windows CRLF or UNIX LF endings.

3. **First boot, initial SSH reachability, and hardware revision reading (AC1, AC3):**
   - Documented hardware cabling, power-on, slot A boot sequence, automatic read-only mounting of `/boot/select`, and connecting over SSH using key authentication to `root@nextoomio.local` (or IP address via DHCP).
   - Documented shell commands to read hardware details upon first flash:
     - Raspberry Pi model: `cat /sys/firmware/devicetree/base/model`
     - CPU and hardware revision code: `grep -E 'Model|Revision|Serial' /proc/cpuinfo`
     - Physical RAM capacity: `free -h` or `/proc/meminfo`
     - ALSA sound card verification: `cat /proc/asound/cards` and `aplay -l`
     - HiFiBerry Amp+ PCB silkscreen revision: visual inspection of the printed silkscreen on the Amp+ PCB (e.g., `PCB Rev 1.0`).
   - Documented initial audio smoke check using `speaker-test` to verify audible output during first flash ([ROADMAP.md](../../../ROADMAP.md) section 2.1).
   - Provided a structured hardware inventory recording table for the bench record.

4. **Repository documentation linkage:**
   - Updated [README.md](../../../README.md) to link to `docs/bench/first-flash.md` in the Repository Layout table and under a dedicated "Test Bench and First Flash" section.

5. **Automated verification suite:**
   - Ran `python3 scripts/check_traceability.py` to verify requirement coverage and markdown relative links.
   - Ran `python3 scripts/check_doc_versions.py` to verify document versions and cross-document section references.
   - Ran `python3 scripts/check_evidence.py --test` and `python3 scripts/check_evidence.py` to validate evidence formatting.
   - Ran `make check` to run the full static verification suite.

The following items require an image build and physical bench hardware:

- **AC3:** Runtime reading and recording of the physical board serial number, effective OTP revision code (`grep 'Revision' /proc/cpuinfo`), and physical HiFiBerry Amp+ PCB silkscreen batch revision from the physical bench hardware upon first flash.
