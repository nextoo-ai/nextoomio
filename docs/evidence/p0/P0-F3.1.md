# Evidence: P0-F3.1 SSH access enabled by a key file on the card

> [!IMPORTANT]
> Secrets, private keys, credentials, tokens, passwords, and addresses of private networks must not be recorded in evidence.

- **Issue:** #15
- **Date:** 2026-11-16
- **Image version and commit:** none (repository only); {{COMMIT}}
- **Hardware model and revision:** none (repository only)
- **Physical access needed:** none

## Procedure

1. **Base image SSH server inclusion and single-image architecture (AC1, D-007, AD-23):**
   - Removed `ssh-server-openssh` from `IMAGE_FEATURES:remove` in `meta-nextoomio/recipes-core/images/nextoomio-image.bb`, fixing defect D-007 where BitBake override semantics stripped OpenSSH from all images.
   - Added `openssh-sshd`, `openssh-keygen`, and `nextoomio-ssh-keys` to `IMAGE_INSTALL:append` in `nextoomio-image.bb`.
   - Updated `meta-nextoomio/recipes-core/images/nextoomio-image-dev.bb` to inherit the single image baseline per AD-23 without separate access controls.
   - Installed OpenSSH systemd preset `meta-nextoomio/recipes-connectivity/openssh/files/99-nextoomio-ssh.preset` disabling `sshd.service`, `sshd.socket`, and `sshd@.service` by default, and set `SYSTEMD_AUTO_ENABLE:${PN}-sshd = "disable"` in `openssh_%.bbappend` so OpenSSH stays stopped unless activated at boot.
   - Installed systemd drop-in `meta-nextoomio/recipes-connectivity/openssh/files/10-authorized-keys.conf` specifying `ConditionPathExists=/run/ssh/authorized_keys`, ensuring the daemon cannot start without validated volatile keys.
   - Configured `meta-nextoomio/recipes-nextoomio/nextoomio-ssh-keys/files/nextoomio-ssh-keys.service` with `After=local-fs.target nftables.service` and `Wants=nftables.service` ensuring the nftables firewall baseline ruleset is loaded before the SSH validator runs.

2. **Boot-time key validator and volatile storage management (AC1, AC3, AC4, AD-23):**
   - Created recipe `meta-nextoomio/recipes-nextoomio/nextoomio-ssh-keys/nextoomio-ssh-keys_0.0.1.bb` providing systemd service `nextoomio-ssh-keys.service` and scripts `nextoomio-ssh-keys-setup.sh` and `nextoomio-ssh-keys-stop.sh`.
   - Implemented discovery of `authorized_keys` or `authorized_keys.txt` on the selector partition (`/boot/select`).
   - Implemented fail-closed validation: if `ssh-keygen` is not available, validation fails immediately, reporting `missing_validator_utility` in diagnostics and keeping SSH disabled.
   - Enforced 16 KiB size limit (at most 16,384 bytes); oversized files cause SSH to remain stopped with diagnostics reporting `file_too_large`.
   - Enforced line-by-line syntax validation: stripped Windows line endings (`\r\n`), rejected key options and unsupported types, verified key structure via `ssh-keygen -l`, enforced RSA key length of at least 3072 bits, and restricted accepted key types to Ed25519, ECDSA, and RSA (>=3072 bits).
   - Enforced maximum count of 16 keys; files with more than 16 keys or 0 keys cause SSH to stay off with diagnostic output.
   - On successful validation, keys are written strictly to volatile tmpfs storage at `/run/ssh/authorized_keys` (mode `0600`, root:root). No authorized keys are ever written to `/root`, `/home`, or persistent partitions.
   - Opened firewall port 22 dynamically in `inet filter input` via `open_firewall_port`, which removes previous rules by handle first to prevent duplicates on re-run, and fails closed if `nft add` fails.
   - Implemented handle-based rule removal (`close_firewall_port`) querying rule handles for `tcp dport 22 accept` in `nextoomio-ssh-keys-setup.sh` and `nextoomio-ssh-keys-stop.sh`.
   - Activated `sshd.service` upon successful validation; if startup fails, the service fails closed and purges volatile keys. On service stop or absent key file, volatile keys are purged, port 22 rule is removed by handle, and diagnostics state that SSH is disabled.

3. **SSH daemon hardening and forwarding restrictions (AC2):**
   - Configured `meta-nextoomio/recipes-connectivity/openssh/files/sshd_config.nextoomio` and installed to `/etc/ssh/sshd_config` with mode `0600`.
   - Removed obsolete `Protocol 2` directive and uninstalled `Subsystem sftp` entry per CQ-R14.
   - Configured `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin prohibit-password`, and `AuthenticationMethods publickey` to strictly reject passwords and interactive logins.
   - Configured `AllowAgentForwarding no`, `AllowTcpForwarding no`, `X11Forwarding no`, `GatewayPorts no`, and `PermitTunnel no` to reject all forwarding.
   - Configured `AuthorizedKeysFile /run/ssh/authorized_keys` directing OpenSSH exclusively to volatile storage.

4. **Persistent host keys on shared data partition across updates and rollbacks (AC5):**
   - Configured `HostKey /data/ssh/ssh_host_ed25519_key` and `HostKey /data/ssh/ssh_host_rsa_key` in `sshd_config.nextoomio`.
   - Configured `nextoomio-ssh-keys-setup.sh` to initialize host keys into persistent storage `/data/ssh/` (mode `0700`, keys `0600`) on first boot if absent, ensuring both slot A and slot B share identical host keys across updates and rollbacks.
   - Added fail-closed check verifying that persistent host keys exist and are non-empty before starting sshd; missing host keys keep SSH disabled and report `missing_host_keys` in diagnostics.

5. **Image and CI artifact cleanliness (AC6):**
   - Verified that no public or private keys are committed to the repository, embedded into recipes, or included in build artifacts. Host keys are generated on-device on first boot into `/data/ssh/`, and authorized keys reside only on the user's card and `/run/ssh/`.

6. **Read-only mounting of selector partition (AC7):**
   - Updated `meta-nextoomio/files/wic/nextoomio-ab.wks.in` partition 1 (`select`) to include `--fsoptions "ro"` so Wic generates an `/etc/fstab` entry with read-only mount options.

7. **Component register update (DoD item 4):**
   - Added `OpenSSH` row (`v0.0.1`, `BSD-2-Clause, BSD-3-Clause, ISC, MIT`, `process`) to section 10 of `ARCHITECTURE.md`.

8. **Static validation enforcement and test suite execution:**
   - Extended `scripts/check_yocto_layer.py` with static validation covering OpenSSH config settings, removal of obsolete directives, preset disabling, systemd drop-in `ConditionPathExists`, setup script limits and rules, handle-based nftables rule deletion, fail-closed handling on missing tools/keys, systemd unit ordering after `nftables.service`, D-007 absence of `ssh-server-openssh` in `IMAGE_FEATURES:remove`, Wic selector partition `--fsoptions "ro"` parsing, and `ARCHITECTURE.md` OpenSSH registration.
   - Executed local verification suite: `make check`, `python3 scripts/check_yocto_layer.py`, `python3 scripts/check_evidence.py --test`, `python3 scripts/check_evidence.py`, `make check-core`, and `make test-core`.

## Missed targets

In accordance with the project owner's decision of 2026-11-15 and the Architect's instructions for issue #15, all Phase 0 software is implemented and statically verified first in author sessions, while full image builds and hardware measurements run on `main` and the bench device afterwards. The following items require an image build and physical bench hardware:
- **Build verification:** BitBake image build of `nextoomio-image` with `openssh-sshd`, `openssh-keygen`, and `nextoomio-ssh-keys` will be verified during full image build on `main`.
- **AC1:** Runtime cold boot on physical Raspberry Pi 4 bench device with `authorized_keys` / `authorized_keys.txt` on FAT partition, verifying SSH daemon start, open port 22, and successful login with matching private key over wired network.
- **AC2:** Runtime authentication tests on physical hardware verifying refusal of password login, keyboard-interactive login, unlisted private keys, and rejection of agent, X11, and TCP forwarding requests.
- **AC3:** Runtime cold boot on physical hardware after removing key file from FAT partition, verifying SSH daemon is stopped, port 22 is closed/filtered, and previous keys are rejected.
- **AC4:** Runtime diagnostic verification on physical hardware for key files >16 KiB, >16 keys, invalid key syntax, RSA keys <3072 bits, and key options, verifying SSH remains off and `/run/nextoomio/diagnostics/ssh.json` records the exact reason; verifying successful acceptance of files with Windows CRLF endings.
- **AC5:** Runtime update or rollback on physical bench device, verifying that the client reconnects without host key mismatch warnings and with the same authorized keys.
- **AC6:** CI package manifest and artifact search verifying zero embedded authorized or private keys.
- **AC7:** Runtime mount table inspection on physical bench device verifying `/boot/select` is mounted read-only (`ro`).
