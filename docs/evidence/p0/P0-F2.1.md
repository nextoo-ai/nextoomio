## Procedure

1. **Kernel command line root partition configuration (AC3, D-004):**
   - Created `meta-nextoomio/recipes-bsp/bootfiles/rpi-cmdline.bbappend` setting `CMDLINE_ROOT_PARTITION ?= "PARTLABEL=root_a"`.
   - Updated `meta-nextoomio/conf/distro/nextoomio.conf` setting `CMDLINE_ROOT_PARTITION ?= "PARTLABEL=root_a"`.
   - Verified that `CMDLINE_ROOT_PARTITION` names slot A's root partition by partition label rather than a fixed device node (resolving defect #36 / D-004 where upstream `meta-raspberrypi` defaulted to `root=/dev/mmcblk0p2` pointing to the FAT `boot_a` partition).

2. **Selector partition content isolation and autoboot.txt deployment (AC4, AC5, D-005):**
   - Created `meta-nextoomio/recipes-bsp/bootfiles/rpi-autoboot.bb` inheriting `deploy` to generate and deploy `autoboot.txt` configured with `[all]` (`tryboot_a_b=1`, `boot_partition=2`) and `[tryboot]` (`boot_partition=2`) to `${DEPLOYDIR}/autoboot.txt`.
   - Updated `meta-nextoomio/conf/distro/nextoomio.conf` configuring `IMAGE_BOOT_FILES_label-select = "autoboot.txt"`, `IMAGE_BOOT_FILES_label-boot_a = "${IMAGE_BOOT_FILES}"`, and exporting both via `WICVARS:append = " IMAGE_BOOT_FILES_label-select IMAGE_BOOT_FILES_label-boot_a"`.
   - Updated `meta-nextoomio/recipes-core/images/nextoomio-image.bb` adding task dependency `do_image_wic[depends] += "rpi-autoboot:do_deploy"` to ensure `autoboot.txt` is deployed before Wic image assembly.
   - Updated `kas/rpi4-64.yml` to append `tryboot_a_b=1` to `RPI_EXTRA_CONFIG` for Raspberry Pi 4 reference machine.
   - Verified that partition 1 (`select`) is populated only with `autoboot.txt`, and slot B partitions (`boot_b` and `root_b`) in `meta-nextoomio/files/wic/nextoomio-ab.wks.in` have no `--source` directive, remaining empty formatted partitions on freshly written media (resolving defect #37 / D-005).

3. **Partition layout, sizing, and MBR table verification (AC2):**
   - Inspected `meta-nextoomio/files/wic/nextoomio-ab.wks.in` against [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.6:
     - Partition 1: `select` (FAT, 64 MiB, active, selector)
     - Partition 2: `boot_a` (FAT, 256 MiB, slot A firmware, config, kernel, overlays)
     - Partition 3: `boot_b` (FAT, 256 MiB, slot B firmware, config, kernel, overlays, inactive initially)
     - Partition 5: `root_a` (ext4, 3072 MiB, slot A read-only rootfs)
     - Partition 6: `root_b` (ext4, 3072 MiB, slot B read-only rootfs, inactive initially)
     - Partition 7: `data` (ext4, 1536 MiB initial, grown on first boot)
     - Bootloader table: `bootloader --ptable msdos` (MBR with logical partitions 5–7).

4. **Static validation enforcement in check_yocto_layer.py and Makefile:**
   - Extended `scripts/check_yocto_layer.py` with automated checks:
     - Verified presence of `rpi-autoboot.bb` and `rpi-cmdline.bbappend`.
     - D-004 check: verified `CMDLINE_ROOT_PARTITION` is defined and fails if fixed device nodes (`/dev/mmcblk*`, `/dev/sd*`) are present, requiring `PARTLABEL=`, `LABEL=`, or `PARTUUID=`.
     - D-005 check: verified `IMAGE_BOOT_FILES_label-select` equals `"autoboot.txt"`, contains no slot artifacts (`Image`, DTBs, overlays, firmware), is present in `WICVARS`, and `nextoomio-image.bb` depends on `rpi-autoboot:do_deploy`.
     - Layout check: verified all partition labels, fixed sizes, active flags, and absence of `--source` on `boot_b` and `root_b`.
   - Updated `Makefile` to include `yocto-validate` as a prerequisite of `check`.

5. **Local verification suite:**
   - Ran `make check`, `python3 scripts/check_yocto_layer.py`, `python3 scripts/check_evidence.py --test`, `python3 scripts/check_evidence.py`, `make check-core`, and `make test-core`.

## Missed targets

- **AC2:** Runtime partition table listing (`lsblk`, `fdisk -l`) on physical bench device.
- **AC3:** Runtime mount inspection (`mount`, `/proc/cmdline`) verifying root filesystem on `root_a` and kernel from `boot_a` on physical bench device.
- **AC4:** Runtime directory listing of mounted `/boot/select` on physical bench device confirming only `autoboot.txt`.
- **AC5:** Runtime inspection of slot B on physical bench device.
- **AC6:** Cold boot timing measurements across ten boots on physical bench hardware.
