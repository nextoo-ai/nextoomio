# Evidence: P0-F3.2 No shell access without a key file

> [!IMPORTANT]
> Secrets, private keys, credentials, tokens, passwords, and addresses of private networks must not be recorded in evidence.

- **Issue:** #16
- **Date:** 2026-11-16
- **Image version and commit:** none (repository only); commit b7fe2369ddaa2a66ea83bbb470e8c8f911d064c6
- **Hardware model and revision:** none (repository only)
- **Physical access needed:** none

## Procedure

1. **Default-off SSH daemon and firewall port closure (AC1, AD-23):**
   - Configured OpenSSH systemd preset `meta-nextoomio/recipes-connectivity/openssh/files/99-nextoomio-ssh.preset` keeping `sshd.service`, `sshd.socket`, and `sshd@.service` disabled by default.
   - Installed drop-in `meta-nextoomio/recipes-connectivity/openssh/files/10-authorized-keys.conf` configuring `ConditionPathExists=/run/ssh/authorized_keys`, ensuring the daemon cannot start without validated volatile keys.
   - Set `SYSTEMD_AUTO_ENABLE:${PN}-sshd = "disable"` in `meta-nextoomio/recipes-connectivity/openssh/openssh_%.bbappend`.
   - In `meta-nextoomio/recipes-nextoomio/nextoomio-ssh-keys/files/nextoomio-ssh-keys-setup.sh`, when no valid key file (`authorized_keys` or `authorized_keys.txt`) is present on `/boot/select`, the service closes firewall port 22 in nftables using rule handle lookup, stops any active sshd process, clears volatile authorized keys, and writes disabled status to diagnostics.

2. **Control interface immutability and selector partition read-only enforcement (AC2, AD-23):**
   - Configured partition 1 (`select`) in `meta-nextoomio/files/wic/nextoomio-ab.wks.in` with `--fsoptions "ro"` ensuring read-only mounting at boot.
   - Inspected all control interfaces (WebUI, API, MQTT, Matter, nx-sysd): none provide endpoints or capabilities to mount `/boot/select` read-write, write files to partition 1, or start `sshd.service`.

3. **Machine-readable and human-readable diagnostics reporting (AC3, AD-23):**
   - Implemented dual diagnostic output in `meta-nextoomio/recipes-nextoomio/nextoomio-ssh-keys/files/nextoomio-ssh-keys-setup.sh` and `nextoomio-ssh-keys-stop.sh`:
     - Machine-readable JSON: `/run/nextoomio/diagnostics/ssh.json`
     - Human-readable text: `/run/nextoomio/diagnostics/ssh.txt`
   - When SSH is enabled with a valid key file:
     - `ssh.json` states `"enabled": true`, `"status": "enabled"`, `"key_count"`, and an array of `"fingerprints"` computed via `ssh-keygen -l`.
     - `ssh.txt` states `SSH access: enabled`, `Status: enabled`, `Keys: <count>`, and lists each fingerprint under `Authorized key fingerprints:`.
   - When SSH is disabled (no key file, invalid keys, or service stopped):
     - `ssh.json` states `"enabled": false`, `"status": "disabled"`, `"reason"`, `"message"`, and empty fingerprints.
     - `ssh.txt` states `SSH access: disabled`, `Status: disabled`, `Reason: <reason>`, `Message: <message>`, and `Fingerprints: none`.

4. **Package manifest artifact publishing and removal of package manager and debug tooling (AC4, D-007):**
   - In `meta-nextoomio/recipes-core/images/nextoomio-image.bb`, enforced `IMAGE_FEATURES += "read-only-rootfs"` and `IMAGE_FEATURES:remove = "debug-tweaks ssh-server-dropbear package-management"`, ensuring no package manager (opkg, dpkg, apt, rpm) and no debug tooling (gdb, strace, debug-tweaks) are packaged into the release image.
   - Removed `ssh-server-openssh` from `IMAGE_FEATURES:remove` and added `openssh-sshd`, `openssh-keygen`, and `nextoomio-ssh-keys` to `IMAGE_INSTALL:append` per AD-23 (resolving defect D-007).
   - In `.github/workflows/yocto-build.yml`, updated artifact upload step `Upload Yocto image, package manifest, SPDX SBOM, and license manifest` to publish `*.rootfs.manifest` and `*.manifest`.

5. **Automated CI static check and self-test verification of failure on deliberately wrong configurations (AC5):**
   - Added validation rules and `--test` self-test suite to `scripts/check_yocto_layer.py`.
   - Configured `Makefile` target `yocto-validate` and `.github/workflows/ci.yml` step `Validate meta-nextoomio layer and kas definitions` to run `python3 scripts/check_yocto_layer.py --test && python3 scripts/check_yocto_layer.py`.
   - Executed `python3 scripts/check_yocto_layer.py --test` to verify that deliberately incorrect configurations trigger check failures:
     - Missing `ConditionPathExists` in drop-in -> check fails.
     - `enable sshd.service` in preset -> check fails.
     - `SYSTEMD_AUTO_ENABLE = "enable"` in bbappend -> check fails.
     - `PasswordAuthentication yes` in `sshd_config.nextoomio` -> check fails.
     - `KbdInteractiveAuthentication yes` in `sshd_config.nextoomio` -> check fails.
     - `PermitRootLogin yes` in `sshd_config.nextoomio` -> check fails.
     - Missing `package-management` in `IMAGE_FEATURES:remove` -> check fails.
     - Missing package manifest pattern in `.github/workflows/yocto-build.yml` -> check fails.
     - Missing `ssh.txt` diagnostics text in setup/stop scripts -> check fails.

6. **Static validation commands and test execution:**
   - Ran `python3 scripts/check_yocto_layer.py --test`
   - Ran `python3 scripts/check_yocto_layer.py`
   - Ran `make check`
   - Ran `make check-core`
   - Ran `make test-core`

### Diagnostics format specification

1. When SSH access is disabled (e.g. no key file on `/boot/select`):
   - JSON format (`/run/nextoomio/diagnostics/ssh.json`):
     ```json
     {
       "enabled": false,
       "status": "disabled",
       "reason": "no_key_file",
       "message": "No authorized_keys or authorized_keys.txt found on selector partition",
       "fingerprints": []
     }
     ```
   - Plain text format (`/run/nextoomio/diagnostics/ssh.txt`):
     ```
     SSH access: disabled
     Status: disabled
     Reason: no_key_file
     Message: No authorized_keys or authorized_keys.txt found on selector partition
     Fingerprints: none
     ```

2. When SSH access is enabled (valid key file on `/boot/select`):
   - JSON format (`/run/nextoomio/diagnostics/ssh.json`):
     ```json
     {
       "enabled": true,
       "status": "enabled",
       "key_count": 1,
       "message": "SSH access enabled with valid keys from selector partition",
       "fingerprints": ["SHA256:4y+..."]
     }
     ```
   - Plain text format (`/run/nextoomio/diagnostics/ssh.txt`):
     ```
     SSH access: enabled
     Status: enabled
     Keys: 1
     Message: SSH access enabled with valid keys from selector partition
     Authorized key fingerprints:
       - SHA256:4y+...
     ```
