## Procedure

Verification commands were run on the working tree of the change commit, on branch `ops/D-062-pipeline-blocks-on-merge-conflic`.

1. **AC1 (Given an open pull request that conflicts with main, when the pipeline runs for its issue, then the author gets a round with the merge in progress and the issue is not labelled state:blocked for the conflict):**
   - Added `try_merge_main(branch, role, cwd)` and `conflict_author_task(number, issue)` in `scripts/agent-pipeline.py`.
   - When an open pull request is found for an issue, `main()` checks out the branch and executes `try_merge_main` to attempt merging `origin/main` before starting review or author.
   - When merging `origin/main` results in merge conflicts:
     - Conflict markers are left in the working tree and the merge remains in progress (`.git/MERGE_HEAD` present).
     - The issue is not labelled `state:blocked`.
     - The author receives a round with task prompt asking to resolve the conflicts in favor of behavior on `main` plus the story's own change and address open review comments.
     - The author's changes are committed as a merge commit and pushed by `deliver()`.
   - Verified offline in `run_self_tests()` Test 17 (`test_d062_ac1_conflicting_pr_gives_author_round_with_merge_in_progress`).

2. **AC2 (Given an open pull request that is behind main and merges cleanly, then the pipeline pushes the merge commit without an author round):**
   - In `try_merge_main()`, when `git merge --no-edit origin/main` succeeds and creates a new merge commit:
     - The merge commit is committed under the role's bot identity.
     - The pipeline pushes the merge commit to `origin/{branch}` using the role push token.
     - `main()` sets `skip_author = True` and `verdict = None`.
     - The pull request proceeds directly to CI checks and Reviewer evaluation without starting an author round.
   - Verified offline in `run_self_tests()` Test 17 (`test_d062_ac2_clean_merge_pushes_without_author_round`).

3. **AC3 (Given an approved pull request that conflicts with main, then AC1 applies and the new head is reviewed again):**
   - When an open pull request was previously approved on GitHub, but conflicts with `origin/main`:
     - `try_merge_main()` detects the conflict upon setup or during auto-merge check.
     - AC1 applies: the author receives a round with merge in progress and resolves the conflict.
     - After the merge commit is pushed, `verdict` is reset and the Reviewer is invoked again to evaluate the new head commit.
   - Verified offline in `run_self_tests()` Test 17 (`test_d062_ac3_approved_conflicting_pr_author_resolves_and_new_head_reviewed`).

4. **AC4 (Given a head commit with a non-required check still in progress, then the Reviewer is not started until it has completed or the timeout is reached):**
   - Modified `wait_for_ci()` in `scripts/agent-pipeline.py`:
     - Evaluates check failure condition over all reported checks: if any check has failed (`FAILURE`, `CANCELLED`, `TIMED_OUT`, `ERROR`, `ACTION_REQUIRED`, `STARTUP_FAILURE`), `wait_for_ci()` returns `False` immediately, reporting a CI failure to the author.
     - Enforces that all required checks are `SUCCESS` and that every check in the rollup has completed (none in `IN_PROGRESS`, `QUEUED`, `PENDING`, `WAITING`, `REQUESTED`, `EXPECTED`).
     - If non-required checks are still in progress, `wait_for_ci()` continues waiting until completion or timeout.
   - Verified offline in `run_self_tests()` Test 17 (`test_d062_ac4_unrequired_check_handling`).

5. **AC5 (Given author output with PR-Summary: only inside a sentence, then the description is unchanged):**
   - Modified `deliver()` in `scripts/agent-pipeline.py`:
     - Looks strictly for line-start `^PR-Summary:\s*` headers.
     - When no line-start header exists, `has_summary` is set to `False` (inline mentions in prose do not qualify).
     - On later rounds, `gh pr edit` is skipped when `has_summary` is `False`, leaving the PR description unchanged, and the round comment notes that no summary was given.
   - Verified offline in `run_self_tests()` Test 17 (`test_d062_ac5_inline_pr_summary_leaves_description_unchanged`).

6. **AC6 (python3 scripts/agent-pipeline.py --test covers AC1 to AC5 and passes):**
   - Added Test 17 to `run_self_tests()` in `scripts/agent-pipeline.py` covering AC1 through AC5 and offline coverage.
   - Updated Test 11 sub-scenario 4 and Test 13 to align with all-checks completion and failure reporting.
   - Executed `python3 scripts/agent-pipeline.py --test` and confirmed exit status 0.
