## Procedure

1. **AC1 (Given a pull request on which every required check succeeded and a check that is not required failed, when the pipeline waits for its checks, then it reports the checks as passed):**
   - Modified `wait_for_ci()` in `scripts/agent-pipeline.py` to evaluate the check failure condition only over `required_checks`:
     `if any(states.get(name) in ("FAILURE", "CANCELLED", "TIMED_OUT", "ERROR", "ACTION_REQUIRED") for name in required_checks):`
     instead of evaluating over `states.values()`.
   - Verified that when all required checks report `"SUCCESS"` and an unrequired check reports `"FAILURE"` (or `"CANCELLED"`, `"TIMED_OUT"`, `"ERROR"`, `"ACTION_REQUIRED"`), `wait_for_ci` returns `True`.
   - Verified that when an unrequired check fails while a required check is still pending or in progress, `wait_for_ci` continues polling instead of failing prematurely, and returns `True` once all required checks succeed.

2. **AC2 (Given a pull request on which a required check failed, when the pipeline waits, then it reports the checks as failed, as before):**
   - Verified that when any required check reports a failure state (`"FAILURE"`, `"CANCELLED"`, `"TIMED_OUT"`, `"ERROR"`, or `"ACTION_REQUIRED"`), `wait_for_ci` returns `False`.
   - Verified behavior when both a required check and an unrequired check fail (`wait_for_ci` returns `False`).
   - Verified behavior when status is reported via GitHub commit status context (`c.get("context")` / `state`).

3. **AC3 (Given the change, when `python3 scripts/agent-pipeline.py --test` runs, then it exits 0 and covers AC1 and AC2 with a substituted pull-request state, without network):**
   - Added Test 13 to `run_self_tests()` in `scripts/agent-pipeline.py` covering AC1 and AC2 completely offline with simulated `pr_state` responses and mock sleep/time functions.
   - Executed `python3 scripts/agent-pipeline.py --test` and confirmed exit status 0.
   - Executed `scripts/check_evidence.py` and `make` to validate repository quality checks.
