## Procedure

Verification commands were run on the working tree of the change commit, based on branch `ops/D-054-pipeline-never-updates-the-pull`.

1. **AC1 (Given an open pull request made by the pipeline, when a later round delivers a commit with a PR-Summary, then the pull-request description equals build_pr_body of that summary (one Refs #<n> line, one role line) and a round comment is posted):**
   - Modified `deliver()` in `scripts/agent-pipeline.py`:
     - Checks if `has_summary` is true (matching `^PR-Summary:` headers, with fallback to `"PR-Summary:" in output`).
     - When `number` is set (a later round on an existing pull request) and `has_summary` is true, calls `gh(["pr", "edit", str(number), "--body", build_pr_body(role, issue, summary)], role=role)` to replace the pull-request description with `build_pr_body(...)`.
     - Calls `gh(["pr", "comment", str(number), "--body", build_round_comment(role, issue, summary)], role=role)` to post the round comment as before.
   - Tested offline in `run_self_tests()` Test 16 (`test_d054_ac1_later_round_with_summary_updates_description_and_posts_comment`):
     - In an isolated git repository with an open pull request (#540), called `deliver()` on a later round with an author summary.
     - Verified that `gh pr edit` was called for PR #540 with `build_pr_body`.
     - Verified that the updated description starts with `Refs #237\n\n`, contains `Refs #237` exactly once, contains exactly one `Role:` line (`Role: DevOps · Model: gemini-3.8-flash-high (Antigravity)`), and ends with the role line.
     - Verified that `gh pr comment` was called with `build_round_comment` containing the cleaned summary and a single `Role:` line.
     - Also verified with `developer` role for PR #541 to confirm proper role line generation (`Role: Developer · Model: ...`).

2. **AC2 (Given a later round whose output has no PR-Summary, then the description is unchanged):**
   - In `deliver()`:
     - When `has_summary` is false on a later round (`number` is set), `gh pr edit` is skipped entirely, leaving the pull-request description unchanged.
     - `gh pr comment` is posted with summary `"The author gave no summary; see the diff."`.
   - Tested offline in `run_self_tests()` Test 16 (`test_d054_ac2_later_round_no_summary_leaves_description_unchanged`):
     - Executed a later round where output contained no `PR-Summary:` section.
     - Verified that `gh pr edit` was not called and the description in GitHub state remained unchanged.
     - Verified that a round comment was posted containing `"The author gave no summary; see the diff."` and the role line.
     - Tested variant where `PR-Summary:` was followed only by whitespace; verified `gh pr edit` was not called, description remained unchanged, and the round comment stated no summary was given.

3. **AC3 (The round task text asks for a summary of the whole pull request at its head):**
   - Added helper `round_author_task(number, issue, why)` in `scripts/agent-pipeline.py`:
     - Generates task prompt: `"Pull request {number} for issue {issue} needs changes: {why}. Read the review and the CI result with \`gh pr view {number} --comments\` and \`gh pr checks {number}\`, and address them. Provide a PR-Summary that describes the whole pull request at its head (what the diff contains now, what was run on it), not only the changes of the round. Follow your role definition."`
     - Used in `main()` both when resuming an existing PR with `CHANGES_REQUESTED` and during the review/CI retry loop.
   - Tested in `run_self_tests()` Test 16 (`test_d054_ac3_round_task_text_asks_for_summary_at_head`):
     - Verified task output for both review requested changes and CI failure.
     - Verified that it names the pull request number, the issue number, the review and checks commands, explicitly asks for a `PR-Summary` describing the whole pull request at its head, and reminds the author not to describe only the changes of the round.
