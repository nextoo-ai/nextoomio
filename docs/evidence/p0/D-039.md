## Procedure

1. **AC1 (Pipeline replaces `{{COMMIT}}` with full change commit hash):**
   - In `scripts/agent-pipeline.py`, update `deliver()` to inspect changed paths for evidence files under `docs/evidence/` that contain the literal marker `{{COMMIT}}`.
   - After creating the change commit, obtain its full 40-character commit hash (`git rev-parse HEAD`), replace `{{COMMIT}}` with that full hash in each matching evidence file, stage each file, and commit them as a follow-up commit before pushing or opening the pull request.
   - Implement `run_self_tests()` in `scripts/agent-pipeline.py` accessible via `python3 scripts/agent-pipeline.py --test`. In a temporary git repository, simulate author changes with an evidence file containing `{{COMMIT}}`, execute the delivery commit and replacement logic, and assert:
     - The change commit contains the author's code changes.
     - The follow-up commit replaces `{{COMMIT}}` with the full 40-character hash of the change commit.
     - The evidence file in the follow-up commit contains `commit <change_commit>` and does not contain `{{COMMIT}}`.
   - Run `python3 scripts/agent-pipeline.py --test` and verify exit code 0.

2. **AC2 (Unresolved `{{COMMIT}}` marker on `main` rejected by evidence check):**
   - In `scripts/check_evidence.py`, define `COMMIT_MARKER = "{{COMMIT}}"` and `is_on_main()` (detecting git branch `main` or CI `GITHUB_REF=refs/heads/main`).
   - In `check_evidence_file(path, is_main)`:
     - When `is_main` is True (or `--main` flag is provided), verify that any occurrence of `{{COMMIT}}` produces an error naming the file: `<rel_path>: contains unresolved marker '{{COMMIT}}' on main`.
     - In field 2 ("Image version and commit"), when `is_main` is False, allow `{{COMMIT}}` as a valid author placeholder prior to pipeline delivery. When `is_main` is True, require a git commit hash (`COMMIT_HASH_RE`).
   - Add unit tests 21–24 in `scripts/check_evidence.py --test` covering:
     - Evidence file with `{{COMMIT}}` on branch (`is_main=False`) passes.
     - Evidence file with `{{COMMIT}}` on `main` (`is_main=True`) fails and names the file.
     - Evidence file with `{{COMMIT}}` alongside a commit hash on `main` (`is_main=True`) fails and names the file.
     - Evidence file without hash and without marker on branch (`is_main=False`) fails with `mandatory field 'Image version and commit' must record a git commit hash`.
   - Run `python3 scripts/check_evidence.py --test` and confirm all 30 assertions pass.
   - Verify CLI behavior with `--main` and on temporary files with unresolved markers.

3. **AC3 (Template and Antigravity brief instruct author to write `{{COMMIT}}` and not a hash):**

     - In the rules section: state that when writing evidence in the change's own pull request, the author writes the literal marker `{{COMMIT}}` in 'Image version and commit' and not a hash; the pipeline replaces it with the change commit hash on delivery.

   - In `scripts/agent-run.sh`:
     - Update the Antigravity prompt brief to instruct: `When writing evidence in the change's own pull request, write the literal marker {{COMMIT}} in the "Image version and commit" field (for example, none (repository only); commit {{COMMIT}}) and not a hash: the pipeline replaces it with the change commit hash on delivery.`
   - Verify by inspecting both files.

4. **Repository verification:**
