## Procedure

1. **Staging area preallocation with real extents and idempotent lifecycle (AC1, AC6, UPD-05, AR-08):**
   - Implemented `StagingStorage` trait in `core/crates/nx-sysd/src/system.rs` with `MockStagingStorage` (in-memory test backend) and `FileStagingStorage` (filesystem backend for `/data/update/staging.swu`).
   - Implemented extent allocation via `posix_fallocate` on Linux and `fcntl(F_PREALLOCATE)` on macOS with explicit sound safety proofs (fd validity, no aliasing, bounds check `capacity <= i64::MAX`) and real return code validation; `get_allocated_size` reports allocated blocks (`st_blocks * 512`) rather than apparent sparse file length.
   - Made `init_staging` idempotent: it preallocates extents only when newly created or smaller than requested capacity, uses `OpenOptions::truncate(false)`, preallocates `staging.meta` (4096 bytes), `journal.0` (4096 bytes), and `journal.1` (4096 bytes), and preserves existing payload metadata across daemon startups or separate process invocations (e.g. between `nx-sysd update stage` and `nx-sysd update validate`).
   - Staged payload writing syncs all written extents via `file.sync_all()`, and persists `staging.meta` in place via `SeekFrom::Start(0)` and `file.sync_all()` without temporary files, renames, or file truncation, guaranteeing zero block allocations on disk writes (UPD-05, AR-01).
   - Enforced typed `StagingError` (`Oversized { attempted, limit }`, `Stream`, and `Storage`). Client stream read errors map to `update_truncated`, while disk write and storage failures map to `data_unavailable`, cleanly separating transport truncation from storage exhaustion (CQ-R5).
   - Enforced that upload cleanup and transaction resets never unlink, truncate, or punch holes in `staging.swu`, preserving the preallocated extents across all failed, completed, or aborted transactions (AC6).
   - Created systemd service `meta-nextoomio/recipes-nextoomio/nx-sysd/files/nextoomio-update-init.service` with `DefaultDependencies=no`, `RequiresMountsFor=/data`, `After=data.mount`, and `Before=basic.target` executing `/usr/bin/nx-sysd update init-staging` on first and subsequent boots.
   - Updated recipe `meta-nextoomio/recipes-nextoomio/nx-sysd/nx-sysd_0.0.1.bb` inheriting `systemd` and packaging `nextoomio-update-init.service`.

2. **Durable transaction state machine and journal reconciliation (AC4, AC5, UPD-04, AR-01, AR-08):**
   - Implemented durable alternating two-record transaction journal (`journal.0` and `journal.1`) in `core/crates/nx-sysd/src/journal.rs` protected by generation numbers and CRC32 checksums.
   - Flushes and syncs data to disk with `file.sync_all()` and directory `sync_all()` to guarantee durability against power failure.
   - Enforced strict state transitions defined in ARCHITECTURE.md section 3.6:

     | Current State | Target State | Trigger Method | Condition / Invariant |
     |---|---|---|---|
     | `Idle` | `Receiving` | `begin_upload` | Starts new upload |
     | `Failed` | `Receiving` | `begin_upload` | Starts new upload following a failed or interrupted transaction (AC4) |
     | `Receiving` | `Receiving` | `begin_upload` | Refused with `UpdateEngineError::Busy` (`update_busy`) (AC5) |
     | `Receiving` | `Installing` | `begin_install` | Refused with `UpdateEngineError::Busy` (`update_busy`) (AC5) |
     | `Receiving` | `Staged` | `stage_upload` | Upload complete, bytes flushed & synced, SHA-256 recorded |
     | `Receiving` | `Failed` | `stage_upload` / `reconcile_boot` | Stream I/O error (`update_truncated`), oversized (`update_oversized`), or boot reconciliation |
     | `Staged` | `Validated` | `validate` | Valid CPIO structure, sw-description, hardware compatibility, schema range, matching artifact digests |
     | `Staged` | `Failed` | `validate` | CPIO truncated, corrupt artifact, hardware/schema mismatch, oversized |
     | `Validated` | `Installing` | `begin_install` | Validated transaction ready for install (P0-F4.4) |
     | `Staged` / `Validated` / `Failed` / `Idle` | `Idle` | `abort` | Resets transaction to Idle; resets payload metadata without reducing extents (AC6) |

     All other state transitions are rejected with `UpdateEngineError::InvalidStateTransition`.
   - In `load_or_init`, unreadable or corrupted records are never swallowed, and if both records are corrupted, returns an explicit error rather than silently resetting state to `Idle`.
   - Boot reconciliation (`reconcile_boot`) is performed on actual boot in `init-staging` (run by `nextoomio-update-init.service` before `basic.target`), reconciling unfinalized `Receiving` transactions left after a power cut or reboot to `Failed` (`update_truncated`), ensuring no transaction is installable and allowing a new upload to start (AC4).
   - In-progress `Receiving` state remains visible across separate CLI invocations (e.g. `status` or a concurrent `stage` process); concurrent uploads and installs are refused as `UpdateEngineError::Busy` (`update_busy`) without clobbering journal state (AC5).
   - Handled stream read errors/dropped connections during upload by transitioning to `Failed` and allowing retry (AC4).
   - Validated declared upload length against actual received byte count, failing with `update_truncated` if an upload ends prematurely before declared length.

3. **Incremental CPIO container and sw-description streaming validation (AC2, AC3, UPD-04):**
   - Implemented pure Rust FIPS 180-4 `Sha256` hasher in `core/crates/nx-sysd/src/sha256.rs` verified against NIST test vectors without external dependencies.
   - Implemented SVR4 new ASCII CPIO archive parser with incremental entry streaming in `core/crates/nx-sysd/src/cpio.rs` verifying 110-byte header format, magic (`070701` / `070702`), trailer (`TRAILER!!!`), and bounded entry `namesize` (≤ 4096 bytes, `MAX_CPIO_NAMESIZE`) to reject malformed headers before allocating memory (CQ-R9).
   - `stage_upload` streams the input reader directly into the staging file on disk via `HashingReader` without memory buffering.
   - `validate` streams CPIO entries incrementally, reading only `sw-description` into memory (with 10 MiB safeguard) and streaming artifact bytes in 64 KB chunks through `Sha256`, preventing out-of-memory kills on target hardware with limited RAM.
   - Enforced bound check `payload_size <= reserved_capacity` before any read operations.
   - Implemented `sw-description` parser in `core/crates/nx-sysd/src/sw_description.rs` extracting `hardware-compatibility`, `config-schema-range`, and artifact definitions.
   - `SlotBackend` trait restricted to read-only queries (`get_active_slot`, `get_default_slot`); active slot detection in `PhysicalSlotBackend` returns an explicit error if `/proc/cmdline` or `/proc/mounts` cannot determine the slot.
   - `UpdateEngine::status` queries live slot values directly from `SlotBackend` rather than static journal copies.
   - In `validate`, verified:
     - `sw-description` is the first file in the archive (failing with `update_invalid_format` otherwise).
     - Target hardware compatibility matching `hardware-compatibility` list (failing with distinct code `update_incompatible_hardware` otherwise).
     - Configuration schema range encompasses device schema version (failing with `update_incompatible_schema` otherwise).
     - Every declared artifact is present in the container and its streaming SHA-256 digest matches declared checksum (failing with distinct code `update_corrupted_artifact` otherwise).
     - Archive is complete and reaches `TRAILER!!!` (failing with distinct code `update_truncated` otherwise).
     - Payload length does not exceed staging reservation (failing with distinct code `update_oversized` otherwise).
   - Verified that on validation success, state transitions to `Validated` bound to a unique `tx_id`, while active slot, default slot, and inactive slot block devices remain completely unwritten and unchanged (AC2, AC3).

4. **CLI interface, robustness, and API specification:**
   - Implemented CLI commands in `core/crates/nx-sysd/src/main.rs`: `nx-sysd update init-staging`, `nx-sysd update stage`, `nx-sysd update validate`, `nx-sysd update status`, and `nx-sysd update abort`.
   - Validated CLI arguments strictly: unparseable `--capacity`, `--declared-length`, or `--schema` values and unknown arguments produce explicit error messages and non-zero exit codes.
   - Documented REST API contracts in `docs/api/openapi.yaml` for `/update/status`, `/update/stage`, and `/update/validate` with `UpdateStatus` schema.
   - Added `update_truncated` and `update_corrupted_artifact` error codes in `core/crates/nx-protocol/src/lib.rs`, `webui/src/i18n/errorMap.ts`, `webui/src/locales/en.json`, and `webui/src/locales/pseudo-dev.json`.

## Missed targets

In accordance with the project owner's decision of 2026-11-15 and the Architect's instructions for issue #19, all Phase 0 software is implemented and statically verified first in author sessions, while full image builds and hardware measurements run on `main` and the bench device afterwards. The following items require an image build and physical bench hardware:
- **Build verification:** BitBake image build (`kas build kas/rpi4-64.yml`) to produce full image containing `nx-sysd` binary and `nextoomio-update-init.service` enabled in systemd will be verified on `main`.
- **AC1:** Runtime verification on physical Raspberry Pi 4 ext4 data partition that first-boot extent preallocation reserves 1 GiB extents and uploading a `.swu` file succeeds after `dd if=/dev/zero of=/data/fill.tmp bs=1M` exhausts remaining free blocks was not measured on bench hardware.
- **AC2:** Runtime execution over SSH of `nx-sysd update stage` and `nx-sysd update validate` with valid Phase 0 `.swu` file, verifying active slot (`root_a`) and default partition (2) in `autoboot.txt` remain unchanged and block device `/dev/mmcblk0p6` has zero byte modifications.
- **AC3:** Runtime execution over SSH of `nx-sysd update validate` with truncated, corrupted, and mismatched hardware bundles verifying distinct error codes printed to stderr/JSON and default partition in `autoboot.txt` remains unchanged.
- **AC4:** Pulling network cable during upload or triggering SIGKILL/reboot and querying `nx-sysd update status` over SSH to verify state is failed/idle and starting a new upload succeeds.
- **AC5:** Concurrent execution of second upload over SSH during active upload confirming exit code 1 and `update_busy`.
- **AC6:** `stat -c %b /data/update/staging.swu` on physical Raspberry Pi 4 ext4 data partition before and after failed/completed uploads confirming exact allocated blocks retained without hole punching.
