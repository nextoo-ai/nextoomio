## Change

`scripts/agent-run.sh` and `scripts/agent-pipeline.py` were taken over from commit `8883a14` (branch `arch/author-engine-codex`), as the issue says, and reviewed. `docs/engineering/agent-team.md` was not taken. Two corrections were made:

- The pipeline's role-and-model line named Codex for every engine other than Antigravity, so with `NEXTOOMIO_ENGINE=claude` (the setting of this very run) it would have named a program that did not run. It now comes from `author_model()`, which follows the same engine selection as `agent-run.sh`: `gpt-6.1-terra (Codex)` by default, `gemini-3.8-flash-high (Antigravity)`, or `opus (Claude Code)`; each model can be overridden with `NEXTOOMIO_CODEX_MODEL`, `NEXTOOMIO_AGY_MODEL`, or `NEXTOOMIO_CLAUDE_MODEL`.
- The engine self-test had been inserted between the assertions of `test_agent_run_pinned_agents`; it now stands on its own as `test_author_engine_selection` and also checks `author_model()` for every engine.

The installed Codex CLI (`codex-cli 0.160.0`) lists the options the script uses in `codex exec --help`: `--model`, `--sandbox` with `workspace-write`, `--color`, and `--output-last-message`. Codex itself was not started with a model (see "Missed targets").

## Procedure

Run on the working tree of the change commit, on branch `ops/D-068-author-engine-codex`, in a session with `NEXTOOMIO_ENGINE=claude` set.

1. `python3 scripts/agent-pipeline.py --test` (with `NEXTOOMIO_ENGINE=claude` in the environment).
2. `env -u NEXTOOMIO_ENGINE python3 scripts/agent-pipeline.py --test` (engine unset, so the module-level line is the Codex default).
3. `make check`.
4. `bash -n scripts/agent-run.sh`.

The self-test stubs `codex` (it writes progress to its output and the prompt to the file named by `--output-last-message`) and `agy`, and stubs `agent-token.sh`, so no network or model is used.
