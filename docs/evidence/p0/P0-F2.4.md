## Procedure

1. **Wired network with DHCP configuration (AC1):**
   - Created default wired Ethernet connection profile in `meta-nextoomio/recipes-connectivity/networkmanager/files/10-default-wired.nmconnection` specifying `type=ethernet`, `ipv4.method=auto`, `ipv6.method=auto`, and `connection.autoconnect=true`.
   - Created `meta-nextoomio/recipes-connectivity/networkmanager/networkmanager_%.bbappend` installing the connection keyfile to `/etc/NetworkManager/system-connections/10-default-wired.nmconnection` with restrictive permissions `0600`.
   - Set `VIRTUAL-RUNTIME_net_manager = "networkmanager"` in `meta-nextoomio/conf/distro/nextoomio.conf`.

2. **Device hostname and mDNS name resolution (AC2):**
   - Configured `hostname = "nextoomio"` in `meta-nextoomio/conf/distro/nextoomio.conf`.
   - Created `meta-nextoomio/recipes-core/base-files/base-files_%.bbappend` writing `nextoomio` to `/etc/hostname` and adding localhost mappings for `nextoomio` and `nextoomio.local` in `/etc/hosts`.
   - Created `meta-nextoomio/recipes-connectivity/avahi/avahi_%.bbappend` and configuration `meta-nextoomio/recipes-connectivity/avahi/files/avahi-daemon.conf` ensuring Avahi publishes the system hostname on `.local` while disabling `publish-hinfo` and `publish-workstation` for least privilege.

3. **Default-deny inbound firewall and extensible ruleset (AC3):**
   - Created baseline nftables ruleset in `meta-nextoomio/recipes-connectivity/nftables/files/nftables.conf` with `type filter hook input priority filter; policy drop;` (default-deny inbound).
   - Permitted loopback (`iif "lo" accept`), established/related connections (`ct state established,related accept`), early invalid state drop (`ct state invalid drop`), and ICMP/ICMPv6 (`ip protocol icmp accept`, `ip6 nexthdr ipv6-icmp accept`).
   - Explicitly allowed inbound mDNS on UDP port 5353 (`udp dport 5353 accept`) so workstation name resolution succeeds.
   - Configured modular extension rule inclusion via `include "/etc/nftables.d/*.nft"` to allow recipes for enabled features to drop additional rule definitions into `/etc/nftables.d/`.
   - Created placeholder/template file `meta-nextoomio/recipes-connectivity/nftables/files/00-default.nft` and `meta-nextoomio/recipes-connectivity/nftables/nftables_%.bbappend` creating `/etc/nftables.d` in the root filesystem.

4. **Non-blocking boot and operation without network or clock (AC4, AC5, AD-21):**
   - Installed systemd preset `meta-nextoomio/recipes-connectivity/networkmanager/files/99-nextoomio.preset` and configured `SYSTEMD_AUTO_ENABLE:${PN}-wait-online = "disable"` in `networkmanager_%.bbappend` to disable `NetworkManager-wait-online.service` and `systemd-networkd-wait-online.service`. This ensures boot reaches `multi-user.target` without delay when no Ethernet cable is connected.
   - Installed systemd preset `meta-nextoomio/recipes-core/systemd/files/99-timesync.preset` in `meta-nextoomio/recipes-core/systemd/systemd_%.bbappend` disabling `systemd-time-wait-sync.service`. Boot does not wait for NTP synchronization or wall-clock convergence (AD-21).
   - Enabled `systemd-timesyncd` in `meta-nextoomio/conf/distro/nextoomio.conf` via `PACKAGECONFIG:append:pn-systemd = " timesyncd"`.

5. **Static validation enforcement and test suite execution:**
   - Extended `scripts/check_yocto_layer.py` with static validation for the required network, Avahi, firewall, and systemd preset files, verifying default-deny policy, mDNS permission, extension inclusion, DHCP connection settings, and non-blocking wait service disabling.
   - Executed local verification suite: `make check`, `python3 scripts/check_yocto_layer.py`, `python3 scripts/check_evidence.py --test`, `python3 scripts/check_evidence.py`, `make check-core`, and `make test-core`.

## Missed targets

In accordance with the project owner's decision of 2026-11-15 and the Architect's instructions for issue #14, all Phase 0 software is implemented and statically verified first in author sessions, while full image builds and hardware measurements run on `main` and the bench device afterwards. The following items require an image build and physical bench hardware:
- **Build verification:** Yocto bitbake image compilation of `nextoomio-image` with `networkmanager`, `avahi-daemon`, and `nftables` will be verified during full image build on `main`.
- **AC1:** Runtime DHCP address acquisition on the physical bench network.
- **AC2:** Workstation-side mDNS hostname resolution of `nextoomio.local` over the physical network.
- **AC3:** Workstation-side TCP and UDP port scan (`nmap`) against the bench device verifying closed/filtered ports.
- **AC4:** Cold boot without network cable connected, verifying boot to multi-user target without timeout delay and automatic interface activation upon cable insertion.
- **AC5:** Cold boot with unset or invalid clock, verifying that boot, local access, and updates continue to operate.
