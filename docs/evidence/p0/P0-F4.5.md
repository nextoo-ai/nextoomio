## Missed targets

In accordance with the project owner's decision of 2026-11-15 and the Architect's instructions for issue #21, all Phase 0 software is implemented and statically verified first in author sessions, while full image builds and hardware measurements run on `main` and the bench device afterwards. The following items require an image build and physical bench hardware:
- **Build verification:** BitBake image build (`kas build kas/rpi4-64.yml`) to produce full image containing `nextoomio-trial-watchdog.service` and updated `nx-sysd` binary will be verified on `main`.
- **AC1 & AC4:** Physical bench verification of Raspberry Pi 4 tryboot hardware selector behavior (`[tryboot]` section in `/boot/select/autoboot.txt` booting partition 3 once and falling back to partition 2 on subsequent reset).
- **AC3:** Physical hardware bench verification of independent 120-second watchdog expiration triggering hardware reset when trial slot is uncommitted.
- **AC5:** Bench power cut during trial slot boot verifying that the hardware power interruption does not lower consumed attempts recorded in the journal.
