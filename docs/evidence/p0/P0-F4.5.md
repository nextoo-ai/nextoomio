## Procedure

1. **Attempt accounting and tryboot selector configuration (AC1, AC4, AC5, UPD-06, AR-01):**
   - Extended `UpdateStatus` and `JournalRecord` in `core/crates/nx-protocol/src/lib.rs` and `core/crates/nx-sysd/src/journal.rs` with `consumed_attempts: u32`.
   - Updated `JournalRecord::commit_state_with_attempts` to persist durable attempt counters with CRC32 checksums across alternating journal files (`journal.0` / `journal.1`).
   - Extended `SlotBackend` trait with `arm_trial_boot(target_slot)` and `is_trial_armed()`.
   - Implemented tryboot autoboot selector in `PhysicalSlotBackend`:
     - Reads/writes `autoboot.txt` in the select partition (typically `/boot/select/autoboot.txt`, overridable via `NEXTOOMIO_SELECT_DIR` or `NEXTOOMIO_AUTOBOOT_TXT`).
     - Preserves the `[all]` section with `tryboot_a_b=1` and `boot_partition=<default_partition>`.
     - Writes `[tryboot]` section with `boot_partition=<target_partition>` (partition 2 for Slot A, partition 3 for Slot B).
   - In `UpdateEngine::request_trial(remote_confirm, auto_reboot)`:
     - Validates that state is `Installed` (or `Trial` for attempt 2) and consumed attempts < 2.
     - Increments attempt count (0 -> 1 on attempt 1, 1 -> 2 on attempt 2).
     - Durably commits state `Trial` and updated attempt count to journal before reboot (AC1, AC5).
     - Arms tryboot selector in `autoboot.txt` for target slot while keeping previous slot default (AC1).
     - Triggers reboot if `auto_reboot` is true.

2. **Local health check evaluation (AC2, AC7, UPD-06, AR-01):**
   - Implemented `HealthReport` struct and `SlotBackend::check_health()` evaluating the 4 mandatory local criteria:
     1. System target reached: checks `systemctl is-system-running` or active target status (overridable via `NEXTOOMIO_HEALTH_SYSTEM_TARGET`).
     2. Data partition mounted: checks `/proc/mounts` or mount table for `/data` (overridable via `NEXTOOMIO_HEALTH_DATA_MOUNTED`).
     3. Configured sound card openable: checks sound-card overlay against `/proc/asound/cards` / ALSA device opening (overridable via `NEXTOOMIO_HEALTH_SOUND_CARD`).
     4. SSH server listening if valid key file present: checks presence/non-emptiness of `/boot/select/authorized_keys` or `authorized_keys.txt`; if present, verifies SSH port listening (overridable via `NEXTOOMIO_HEALTH_SSH_KEY_PRESENT` and `NEXTOOMIO_HEALTH_SSH_LISTENING`).
   - AC7 verification: health check requires no network connectivity, NAS mounts, Music Assistant, or Home Assistant connectivity; evaluation is strictly local.

3. **Trial deadline watchdog service (AC3, UPD-06, AR-01):**
   - Implemented `UpdateEngine::run_trial_watchdog(deadline_secs, poll_interval_ms)` in `core/crates/nx-sysd/src/engine.rs`:
     - Measures elapsed kernel uptime via `/proc/uptime` (or `NEXTOOMIO_TEST_UPTIME_SECS`).
     - Carries the boot budget through boot stages so application startup does not reset the timer.
     - Polls transaction state until state transitions to `Committed` (watchdog exits cleanly) or 120s deadline expires.
     - If deadline expires while uncommitted, triggers system reboot back to previous default slot (AC3).
   - Created systemd unit `meta-nextoomio/recipes-nextoomio/nx-sysd/files/nextoomio-trial-watchdog.service` and configured it in `nx-sysd_0.0.1.bb` to start before `basic.target`.

4. **Attempt progression, recovery, and contradictory record handling (AC4, AC5, AC6, D-026):**
   - In `JournalController::reconcile_boot(running_slot)`:
     - Detects contradictory records (target slot equals default slot, or consumed attempts > 2) and transitions to `Failed` (`update_record_contradictory`), keeping default slot and preventing trial (AC6).
     - When reboot occurs on the previous slot during a trial (running_slot != target_slot):
       - Attempt 1 failure: arms attempt 2 (`consumed_attempts = 2`), re-arms tryboot selector, and leaves state `Trial` (AC4).
       - Attempt 2 failure: transitions to `Failed` with error code `update_trial_exhausted`, staying on previous slot without retrying (AC4).
     - Process restarts or power cuts during a trial never decrease `consumed_attempts` (AC5).
     - Enabled recovery from `Committing` to `Failed` (D-026) and discarding unwanted staged/validated/installed transactions via `abort()` / `can_transition_to`.

5. **CLI commands and OpenAPI schema update:**
   - Implemented CLI subcommands in `nx-sysd`:
     - `nx-sysd update trial [--remote-confirm] [--no-reboot] [--dir <path>]`
     - `nx-sysd update health-check [--dir <path>]`
     - `nx-sysd update trial-watchdog [--deadline <secs>] [--poll-interval <ms>] [--dir <path>]`
   - Updated `docs/api/openapi.yaml`: added `POST /update/trial`, `GET /update/health-check`, `consumed_attempts` property on `UpdateStatus`, and `HealthReport` schema.

- **AC1 & AC4:** Physical bench verification of Raspberry Pi 4 tryboot hardware selector behavior (`[tryboot]` section in `/boot/select/autoboot.txt` booting partition 3 once and falling back to partition 2 on subsequent reset).
- **AC3:** Physical hardware bench verification of independent 120-second watchdog expiration triggering hardware reset when trial slot is uncommitted.
- **AC5:** Bench power cut during trial slot boot verifying that the hardware power interruption does not lower consumed attempts recorded in the journal.
