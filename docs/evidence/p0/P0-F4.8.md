## Procedure

1. **Implementation of automated power-loss resilience tooling (`scripts/bench/power_loss.py`):**
   - Implemented `PowerLossRunner` orchestrating automated power-loss resilience testing across four distinct update transaction phases in accordance with [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.6:
     - **Upload Phase:** Cuts power during update stream to `/data/update/staging.upload.swu`.
     - **Install Phase:** Cuts power while writing raw boot and root partition contents to the inactive system slot (`nx-sysd update install`).
     - **Trial Boot Phase:** Cuts power during trial boot or trial runtime before remote confirmation is received (`nx-sysd update trial --remote-confirm`).
     - **Commit Phase:** Cuts power during selector switch and journal update (`nx-sysd update commit`).
   - Implemented `PowerCutScheduler` ensuring power cut timers finish executing before restoring power, and verifying that the interruption occurred while the phase command was actively running.
   - Implemented `PowerController` abstraction supporting command-based remote switching (`CommandPowerController`, via user/bench-supplied power command) and simulated execution (`MockPowerController`). A run with `--mock-power` explicitly produces a NON-GATE report.
   - Implemented credential and URL token sanitization (`redact_text()`), redacting Bearer tokens, passwords, Basic auth headers, and query credentials from all logs and reports (CQ-R6).
   - Implemented argument parsing with host, user, and option injection validation (CQ-R7).

2. **Implementation of seeded random delay algorithm for varied moments (AC3):**
   - Varied power cut moments are generated deterministically using a seeded PRNG (`random.Random(seed)`).
   - Delays are sampled from phase-specific intervals:
     - `upload`: $[0.5, 4.0]$ s.
     - `install`: $[1.0, 10.0]$ s.
     - `trial`: $[2.0, 15.0]$ s.
     - `commit`: $[0.05, 0.8]$ s.
   - The report records the PRNG seed, exact cut delay, and timestamp for every trial across all cases.
   - Unreachability before trial start is captured and recorded as a failed trial with `physical_access_needed = True` blocking the gate.

3. **Implementation of state consistency and recovery verification (AC1, AC2, AC4):**
   - **AC1 Verification (`_verify_complete_image`):** Verifies that after power restoration, the device boots within timeout (120s), answers SSH, runs systemd PID 1 (`kill -0 1`), and parses `mount` output to confirm the root filesystem is mounted read-only (`ro` in mount options) on the partition matching the active running slot (SYS-04). If the mount source is `/dev/root`, it is resolved against the kernel command line (`root=`) in `/proc/cmdline` to ensure partition matching (CQ-R4, CQ-R2).
   - **AC2 Verification (`_verify_ac2_state_consistency`):** Checks updater state machine invariants against `nx-sysd update status --json` in accordance with [ARCHITECTURE.md](../../../ARCHITECTURE.md) section 3.6:
     - Interrupted upload/install boots original slot $S_{orig}$; default selector remains $S_{orig}$; inactive slot is not installable or bootable; update state is `idle` or `failed`.
     - Interrupted trial consumes its attempt (`trial_attempts >= 1`).
     - Interrupted commit resolves cleanly to either $S_{target}$ with `committed` or reverts to $S_{orig}$ in a resolved state (e.g. `failed` or `idle`, never `committing`, `trial`, or `installed`), never undefined (CQ-R4).
   - **AC4 Verification (`_execute_subsequent_deploy`):** Deploys a fresh valid `.swu` to completion with remote confirmation (`nx-sysd update confirm`), confirming active slot alternation and durable commit.

4. **Automated unit and integration test suite (`scripts/bench/test_power_loss.py`):**
   - Implemented 18 automated self-tests exercising runner logic against simulated in-memory devices (`PowerLossMockDevice`):
     - `test_ac1_ac2_ac4_upload_interruption`: exercises upload interruption recovery, state consistency, and subsequent deploy against simulation.
     - `test_ac1_ac2_ac4_install_interruption`: exercises install interruption recovery, inactive slot unbootable, and subsequent deploy against simulation.
     - `test_ac1_ac2_ac4_trial_interruption`: exercises trial interruption attempt consumption and subsequent deploy against simulation.
     - `test_ac1_ac2_ac4_commit_interruption`: exercises clean commit resolution and subsequent deploy against simulation.
     - `test_commit_cut_waits_for_reboot_when_device_stays_reachable_on_old_slot`: verifies commit case waits for reboot completion into target slot and trial state when device stays reachable during shutdown before commit starts (CQ-R4, CQ-R1).
     - `test_commit_cut_interrupted_reverting_to_previous_slot_with_unresolved_state_fails`: verifies interrupted commit returning to initial slot with unresolved state fails consistency check (CQ-R4).
     - `test_ac1_fails_when_rootfs_mounted_read_write`: verifies `_verify_complete_image` rejects read-write rootfs mount or wrong partition.
     - `test_ac1_resolves_dev_root_against_cmdline`: verifies `_verify_complete_image` resolves `/dev/root` mount against `/proc/cmdline` (CQ-R4, CQ-R2).
     - `test_ac2_trial_missing_or_zero_attempts_fails`: verifies `_verify_ac2_state_consistency` fails if trial attempt counter was not incremented.
     - `test_ac3_ten_trials_varied_moments_all_cases`: exercises full 40-trial matrix (10 per case) with seed 42, varied delays, 0 physical access, and report generation against simulation.
     - `test_ac3_device_failure_flags_physical_access_and_blocks_gate`: verifies device failure flags physical access requirement and blocks gate.
     - `test_unreachable_device_before_trial_records_physical_access_and_blocks_gate`: verifies unreachability before trial start is recorded as a failed trial requiring physical access.
     - `test_upload_finished_before_cut_raises_error`: verifies upload finishing before cut raises an error and is not marked as an interruption.
     - `test_fewer_than_ten_trials_is_non_passing`: verifies runs with fewer than 10 trials per case are marked as NON-GATE.
     - `test_credential_redaction_cq_r6`: verifies Bearer tokens, Basic auth, and passwords are redacted.
     - `test_command_power_controller_redacts_credentials`: verifies command logger redacts credentials.
     - `test_cq_r7_unsafe_identifiers_rejected`: verifies option injection rejection and required power command configuration.
     - `test_json_and_markdown_report_structure`: verifies JSON and Markdown report formatting.
   - Integrated into `Makefile` under `check-bench` target.

## Missed targets

In accordance with the project owner's decision of 2026-11-15 and the Architect's instructions for issue #24, all Phase 0 software is implemented and statically verified first in author sessions, while full BitBake image builds and hardware measurements on real bench hardware run on `main` and the bench device afterwards. The following items require an image build and physical bench hardware:
- **AC1:** Runtime execution of electrical power removal via switched AC power outlet during upload, install, trial, and commit phases on physical Raspberry Pi 4 + HiFiBerry Amp+ hardware, and timing of physical board reboot and SSH availability.
- **AC2:** Physical block device and filesystem journal recovery measurements on real SD card partitions (`boot_a`/`boot_b`, `root_a`/`root_b`, and `/data`) following abrupt power loss during partition writes and FAT selector commit.
- **AC3:** Execution of 40 consecutive real power-loss cycles via switched outlet across all four phases to demonstrate zero required physical site visits on the reference bench setup.
- **AC4:** Physical end-to-end deployment, flashing, and confirmation of a valid update image on hardware following real power-cut recovery.
